> 升级前先读「升级检查清单」；只关心某个模块时查「按模块定位」。

## v2.6.3 — 会话安全与握手帧（2026-10-21）

### Breaking Changes

1. **`packet` 接口重写**：`Packer.Read` 返回 `(FrameType, int64, buffer.Buffer, error)`（原 `bool` 心跳标记）；`PackMessage(route, seq int32, data []byte)` 取代 `PackMessage(*Message)`，`packet.Message` 类型删除；新增 `PackHandshake` / `ExtractHandshake`；`ExtractRouteSeq` 保留。
2. **header 布局调整**：删除 bit6「心跳时间标志」，恢复 `h(1 bit) + extcode(7 bit)`；握手帧使用 `extcode = 1`（header `0x01`），心跳是否带时间改由 **size** 区分（`size=1` 不带、`size=9` 带 8 字节时间）。
3. **会话安全迁移**：`crypto/{aead,aesgcm,chacha20poly1305,handshake}` 迁至 `core/security/...`；`WithSessionSecurity` 改为 `(signer crypto.Signer, suites ...aead.Suite)`；`handshake.MakeAAD` 需要 key epoch，AAD 为 11 字节；默认套件为 AES-256-GCM + ChaCha20-Poly1305。
4. **crypto 收敛**：删除 `crypto.Verifier` 接口与 `RegisterEncryptor` / `InvokeEncryptor` / `RegisterSigner` / `InvokeSigner` 四个全局函数；验签合并进 `Signer.Verify`；`rsa.Verifier` / `ecc.Verifier` 删除。
5. **防篡改机制移除**：`WithEnableTamperProtection`（client/node）、`etc.cluster.{client,node}.enableTamperProtection`、`errors.ErrTamperedMessage` 全部删除，改用握手会话安全；`WithEncryptor` 只保护 payload。
6. **安全默认值加固**：RSA 加密默认 **OAEP**（旧行为需显式 `NORMAL`）；私钥文件权限 0600、ECC 密钥目录 0700；pprof 默认监听 `127.0.0.1:0`（远程访问需显式 addr）；Digest 认证 nonce 绑定请求目标。
7. **network 接口新增必需方法**：`Server` / `Client` 均需实现 `OnHandshake(handler HandshakeHandler)`，自定义网络实现需补齐。
8. **路由签名**：`Actor` / `Proxy` / `Router` 的 `AddRouteHandler` 在 v2.6.3 短暂支持任意整数泛型，v2.6.4 又收回为 `int32`（见下节），不要依赖泛型写法。

### 新特性

- **握手式会话加密**：X25519 密钥交换 + 签名 ServerHello + HKDF 派生双向密钥 + 64-bit 重放窗口；Gate 侧握手状态机、上行解密、下行加封。
- Gate 握手超时（默认 5s，`WithSessionSecurityHandshakeTimeout`）；超时后关闭未完成会话。
- `Actor.Processor()`：在 Actor 读锁下返回处理器，销毁后返回 nil。
- `encoding/json` 支持 `stdjson` 构建标签，切换到标准库 `encoding/json/v2`（默认仍为 sonic）。
- `core/stat` 使用真实创建时间（Linux statx / BSD birth time），修正 `IsFile` 仅对普通文件为 true。
- WebSocket 分片缓冲通过 `NextWriter` 流式写出；新增 `network/ws/writer.go`。
- 缓冲与打包：`core/buffer` 新增 headroom、`Bytes.Prepend` / `Truncate`、`NocopyBuffer.Slice`；新增 `PackMessageBuffer` / `ExtractMessage` 与 `MessageBufferHeadroom`。

### 性能

- 安全消息路径零拷贝：`SealMessage` / `OpenMessage` 复用池化 nonce 与 AAD 工作区；密文下行、明文上行都预留对齐 headroom，保持单节点帧。
- 消息 header 原地预置，避免每包一次 payload 拷贝。

### 修复

- 会话安全生命周期：封包与网络入队串行化以保证计数器顺序；断线唤醒待完成握手；握手超时后关闭未完成会话（默认 5s，可配置）；克隆套件切片隔离调用方修改；保留 RSA/ECC 密钥解析错误。
- 节点请求：拒绝空 payload（v2.6.6 又恢复为空消息），缓存解密明文避免重复解密。

### 依赖

- 新增 `golang.org/x/crypto`（ChaCha20-Poly1305）；sonic 1.15.4；`golang.org/x/sys` 直接依赖（statx）。

## v2.6.4 — 路由签名收敛为 int32（2026-10-22）

### Breaking Changes

- `Actor.AddRouteHandler` / `Proxy.AddRouteHandler` / `Router.AddRouteHandler` 的参数从泛型 `T constraints.Integer` 收回为 **`route int32`**。如果传的是 `uint32` / `int64` 等**有类型变量**，需要显式转换；无类型常量不受影响。

### 其他

- 移除 `golang.org/x/exp` 依赖（不再使用 constraints 泛型）。
- 各子模块 `go.mod` 对齐 v2.6.4；README 客户端列表更新（C# 客户端）。

## v2.6.5 — 吞吐与内存优化（2026-10-26）

### Breaking Changes

1. **`session` 包删除**：会话类型迁移到 `cluster` 包——`session.Kind` → `cluster.Session`，`session.Conn` / `session.User` → `cluster.Conn` / `cluster.User`；会话注册表收进 Gate 内部，不再对外导出。
2. **`Proxy.PackMessage` 返回 `buffer.Buffer`**（原 `[]byte`），所有权转移给调用方，必须 `Release()`；`PackBuffer` 仍返回 `[]byte`。Node / Mesh 同步调整。
3. **客户端路由 Context 池化**：`cluster/client` 的路由上下文来自 `sync.Pool`，**handler 返回后不得继续持有或引用** `Context`（需要异步使用请先复制字段）。
4. 内部 `session` API 重命名并内聚（`bind` / `unbind` / `uid` 等），仅影响直接改框架源码的项目。

### 新特性与性能

- 编解码 `encoding.Appender`：json / proto / msgpack 支持把编码结果追加到调用方缓冲，配合池化缓冲实现原地打包。
- `core/buffer` 新增 `Bytes.Resize`，配合 Appender 在预留尾部直接提交编码长度。
- 读帧预留 32 字节 headroom（`packet.ReadBufferHeadroom`），传输层 deliver / push 头原地预置，避免 payload 拷贝。
- Node 调度批量出队：单次唤醒最多处理 64 个路由请求，保持 FIFO 串行。
- Gate 会话表 256 分片（连接/用户/频道独立分片）、binding lock 分片、频道订阅不可变快照、`Stat` 改为 O(1) 原子计数。
- 单目标 `Push` 走 direct/indirect 快路径，跳过 Multicast 包装；`PushArgs.Disconnect` 正常透传。
- `core/chains` 节点池化；客户端路由 Context 池化；Node 请求复用 defer 链。
- `utils/xcall.Recover` 导出，供自定义 goroutine 统一做 panic 恢复；`Call` / `Backoff` 复用该实现。

### 修复

- Gate 绑定与断开/销毁串行化：同连接绑定请求串行、按用户加锁、断开先摘除本地会话再清理定位；Destroy 等待已接入连接的断开回调。
- 安全会话关闭改为专用 goroutine，避免在 receive 回调里同步 Close 造成自锁。
- 客户端 `Destroy` 并发关闭连接；hook panic 不再卡住关闭等待。
- `Proxy.PackMessage` 返回池化缓冲后由调用方释放，修复 header writer 泄漏。

## v2.6.6 — 空载荷与配置轮询（2026-11-04）

### 行为变更

- **节点请求空 payload 恢复为合法**：按空消息处理、不修改解析目标；撤销 v2.6.3 的 `ErrInvalidMessage` 拒绝行为。
- `config/nacos` 配置组轮询间隔从 3s 调整为 **10s**，监听驱动的配置内容更新不受影响。

### 其他

- 仅版本号与 28 个子模块依赖对齐；README 吞吐口径统一为 Gate→Node 500 并发单线程 430K+ TPS。

## v2.6.7 — 限流、IP 准入与 IPv6（2026-11-09）

### 新特性

- **`limiter` 限流体系**：顶层 `limiter`（Maker / Limiter 抽象、Rule 归一化、FailOpen/FailClosed）、`limiter/memory`（进程内令牌桶）、独立子模块 `limiter/redis/v2`（Lua 令牌桶 + 熔断 + 定点状态）。
- **Gate per-connection GCRA 限流**：整数 GCRA、256 分片 + free list、cache line padding，超出配额丢弃业务帧并在连续违规后断连；握手帧/心跳帧绕过。
- **Gate per-IP 准入与临时封禁**：`[cluster.gate.guard]` 支持每 IP 并发连接上限、准入速率、白名单、违规累计后按窗口递增封禁时长（默认不开启自动封禁）。
- **IPv6 双栈监听**：`:port` 与 `[::]:port` 在 TCP/WS/KCP/QUIC 全部双栈；`0.0.0.0:port` 仍只监听 IPv4；新增 `utils/xnet.IP2Bytes` / `Bytes2IP`。
- **`Conn.CloseIf(id)`**：仅当连接 ID 匹配时关闭，避免连接池复用误关新连接。
- **Nacos 3.x 管理端支持**（`config/nacos`）：v3 登录鉴权、v3 list/export 批量拉取、令牌缓存与失败回退；`registry/nacos` 升级 SDK v2.3.6。
- **Actor 事件订阅索引**：按事件索引可调度 Actor，事件分发不再全量扫描。
- 其他：`Connect`/`Disconnect` 按连接串行化、Connect handler 固定在 read goroutine、hook panic 隔离、实例注册/刷新/注销串行化。

### Breaking Change / 兼容边界

- **get-ip 协议统一为一次 RPC**，响应按 4 字节（IPv4）/ 16 字节（IPv6）自描述；移除了旧的协商回退，**Node 与 Gate 必须同版本升级**（旧 Node 拒绝 16 字节响应，旧 Gate 对 IPv6 会话返回 0.0.0.0）。
- 删除未使用的 `core/location` IP 归属地解析包与 `utils/xlocation` 相关实现；`core/limiter` 同时移除（令牌桶并入 `limiter/memory`），依赖这些内部包的项目需迁移。
- 外部公开 API 其余保持兼容；`WithSessionSecurity` 的选项分组属于内部重构。

### 修复

- 连接关闭语义：limiter 触发的 Close 延迟到 read loop 外、按 retry 间隔重发、未准入连接也释放 bucket。
- Gate 事件顺序：Connect 在握手确认后触发，Disconnect 不早于 Connect；早到握手帧缓冲重放，已确认后再收到握手帧直接断连。
- 注册中心：Register/Refresh/Deregister 加锁串行化，Destroy 关闭 linker 缓存的 RPC 客户端。
- 批量推送 fan-out 限制 64 并发；单目标批量推送不再误报错误。
- `Node.Close` 在最后一次等待完成后正确唤醒；hook panic 由 defer Done 兜底。

## v2.6.8 — 配置中心与注册中心加固（2026-11-16）

### Breaking Changes

1. **config 实现迁移**：核心实现从顶层 `config` 包迁移到 `core/config`（含 `core/config/file`），顶层 `config` / `config/file` 保留为 facade（`Configurator` / `Source` 等以类型别名保留），公共 API 路径不变；`config/file` 不再导出 `Source` 类型（`NewSource` 仍返回 `config.Source`）。直接依赖内部实现或 `core/pattern` 的代码需要调整（`core/pattern` 未在正式版本中对外暴露）。
2. **`consul.WithContext` 选项删除**：context 由 configurator 通过 `Source.Load` / `Source.Watch` 传入。
3. **Nacos/Polaris 嵌套 dataId 以 basename 作为 key**：`path/to/game.toml` 的配置 key 变为 `game`（`config.Get("game.xxx")` 可读）；不同路径下同名文件会冲突，需避免。
4. **路由元数据编码变更**：Consul/Nacos/Polaris 改为紧凑 flag range（Consul 按 512 字节分块）；**新版可解码旧格式，旧版不能解码新格式**，滚动升级时应先升级读取方或安排整体升级窗口。

### 新特性

- **`files` 选项**：所有 config source（file/consul/etcd/nacos/polaris）支持精确文件名 + `*` 通配符，约束 Load / Store / Watch 的范围；显式 Load/Store 落在列表外返回 `errors.ErrFileNotConfigured`。Nacos 通配符会转成服务端 blur 关键字查询。
- **配置可靠性**：启动加载失败的 source 后台重试并合并；watcher 异常/读错误按有上限指数退避重连；watch 回调 panic 隔离且串行执行；只发布实际变更；Close 与在途 Load/Store 串行化；拒绝重复 source。
- **`Value.Scan` 重写**：支持 struct `default` 标签（递归）、跨类型标量/结构/映射/切片转换、json tag 匹配、嵌入结构提升、单遍 JSON 扫描与零分配解码。
- **注册中心**：Consul/Etcd 增加 closed 状态与 watcher 重试/幂等 Stop；Nacos/Polaris 跳过无效实例，Nacos 在全实例解析失败时保留上一份快照；路由数量有上限；Polaris 新增 `cacheDir`/`logDir`。
- **新导出错误**：`ErrInvalidIndex`、`ErrIndexOverflow`、`ErrIndexTooLarge`、`ErrInvalidRoutes`、`ErrTooManyRoutes`、`ErrNotFoundConfigurator`、`ErrClosedConfigurator`、`ErrClosedConfigSource`、`ErrFileNotConfigured`、`ErrInvalidFilePath`、`ErrConfigAuthRequired`、`ErrAllInstancesParseFailed`。
- Etcd config 的 `timeout` 明确为 watcher 读取超时（初始快照 + resync）；Polaris config 新增 `cacheDir` / `logDir`；`encoding/json` 的 `omitempty` 对齐 sonic（false / 0 省略），并新增 `UnmarshalString` 避免字符串解码拷贝。
- 依赖：sonic 1.15.5、polaris-go 1.7.2（Nacos SDK 2.3.6 自 v2.6.7 起）。

### 修复

- 配置路径校验：拒绝空、绝对、根、目录穿越与通配符作为显式 Load/Store 条目；标量根配置可正常加载；空/不可解码内容保留旧值。
- 变更替换语义：整份替换变更的配置（删除的 key 会真正消失）；只通知实际存储的配置。
- file source：只 watch 目录、新建目录补加载、rename 重载、临时文件原子写。
- Nacos：固定文件列表监听重试、v3 鉴权恢复、分页/导出缓存、嵌套 dataId 合并通知；Polaris：固定文件订阅重试、logger 只初始化一次。
- 配置语义收紧：`Load` 只取首个非空文件；`Close` 后读继续、写报错；未安装配置器返回 `ErrNotFoundConfigurator`；nil Watch 回调忽略。

| 13 | `consul.WithContext` | v2.6.8 | 删除该选项，context 由框架传递 |
| 14 | 嵌套 dataId key | v2.6.8 | 改为 basename 作为 key，避免不同路径同名文件 |
| 15 | 路由元数据滚动升级 | v2.6.8 | 新版可读旧格式，旧版读不了新格式：先升级所有读取路由元数据的实例，或整批升级 |
| 16 | 配置错误判断 | v2.6.8 | 用 `errors.Is` 匹配新增导出错误 |

## 兼容性说明

- **同一大版本内**：v2.6.3 与 v2.6.5 的破坏性变更集中在 `packet` / `crypto` / `session` 三个包，业务代码按上表迁移即可；v2.6.4 的破坏点仅是 `AddRouteHandler` 的 `int32` 签名，v2.6.6 基本是行为微调。
- **混合版本集群**：v2.6.7 的 get-ip 协议要求 Node/Gate 同版本；v2.6.8 的路由元数据只保证「新读旧」，不保证「旧读新」。
- **配置兼容**：v2.6.8 的 `files` 过滤默认不启用，未配置时行为与旧版一致；配置 key 的 basename 规则对 Nacos/Polaris 嵌套 dataId 生效。
- **文档基准**：本技能所有 API 签名与配置键以 v2.6.8 源码为准；升级到更高版本前，请用对应 tag 的源码复核。
