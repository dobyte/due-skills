# 配置管理

## 概述

Due v2 的配置文件由 config 配置源加载，格式支持 TOML、JSON、YAML、XML（框架示例默认使用 TOML），支持多层级配置与配置热加载。配置系统分为两层：
- **etc**：框架启动配置，仅通过配置文件读取，用于初始化核心组件
- **config**：业务配置，可通过配置中心读取与写入，用于游戏逻辑参数

## 配置文件结构

### 目录结构

```
项目根目录/
├── etc/
│   └── etc.toml          # 框架启动配置（默认目录 ./etc）
├── config/
│   └── game.toml         # 游戏业务配置（默认目录 ./config）
└── main.go
```

> 说明：配置源会加载目录下的全部文件，每个文件的文件名（不含扩展名）即为该配置的一级命名空间。例如 `etc.toml` 中的内容通过 `etc.xxx` 模式读取，`game.toml` 中的内容通过 `game.xxx` 模式读取。

### 配置优先级

- **etc 启动配置**：默认读取 `./etc` 目录，仅支持通过配置文件读取，不通过主控管理服动态修改。可通过环境变量 `DUE_ETC` 或运行参数 `-etc` 指定 etc 目录：

```bash
DUE_ETC=/path/to/etc ./game-server
# 或
./game-server -etc /path/to/etc
```

- **业务配置 config**：默认读取 `./config` 目录，路径可通过 etc 配置项 `etc.config.file.path` 或 `file.WithPath` 选项指定。

- **运行模式 mode**：取值优先级（后者覆盖前者）为 配置文件 `etc.mode` < 环境变量 `DUE_MODE` < 运行参数 `-mode` < `mode.SetMode()`。

## 启动配置（etc）

### 核心配置项

#### 1. 进程配置

```toml
# 进程号文件路径
pid = "./run/due.pid"

# 统一时区设置，项目中时间获取请使用 xtime.Now()
timezone = "Local"

# 容器关闭最大等待时间。支持单位：ns、us、ms、s、m、h、d。默认为 0s
shutdownMaxWaitTime = "0s"
```

#### 2. 运行模式

```toml
# 运行模式：debug、test、pre-release、release
mode = "debug"
```

**环境变量覆盖：**
```bash
export DUE_MODE=release
```

#### 3. 网关服配置

```toml
[cluster.gate]
  # 实例ID，集群中唯一。留空默认自动生成唯一的实例ID

    key = "value"

  [cluster.gate.linker]
```

## 业务配置（config）

### 配置读取

业务配置通过 config 配置器读取，使用前需先设置配置器（配置源），例如使用文件配置源：

```go
import (
    "github.com/dobyte/due/v2/config"
    "github.com/dobyte/due/v2/config/file"
)

config.SetConfigurator(config.NewConfigurator(config.WithSources(file.NewSource())))
```

`config.Get` 返回 `value.Value`，可转换为各类基础类型或扫描到结构体：

```go
import "github.com/dobyte/due/v2/config"

// 读取单个配置项
maxLevel := config.Get("game.maxLevel", 100).Int()

// 读取配置到结构体
type GameConfig struct {
    MaxLevel    int     `json:"maxLevel"`
    ExpRate     float64 `json:"expRate"`
    DropRate    float64 `json:"dropRate"`
}

gameConfig := &GameConfig{}
if err := config.Get("game").Scan(gameConfig); err != nil {
    log.Errorf("读取游戏配置失败: %v", err)
}
```

Configurator 的其他常用方法：

```go
config.Has("game.maxLevel")            // 判断配置是否存在
config.Set("game.maxLevel", 200)       // 写入配置
config.Match("game.a", "game.b").Get() // 按模式顺序匹配，返回首个命中的值
config.Load(ctx, file.Name, "game.toml") // 从指定配置源加载配置文件
config.Store(ctx, file.Name, "game.toml", content) // 写入配置文件（需可写模式）
config.Watch(cb, "game", "config")     // 监听指定配置变化
```

### 配置热加载

```go
// 监听配置变化；names 用于过滤要监听的配置名（文件去扩展名），为空则监听全部
config.Watch(func(names ...string) {
    log.Printf("配置变更: %v", names)

    // 重新读取配置
    for _, name := range names {
        if name == "game" {
            reloadExpRate(config.Get("game.expRate").Float64())
        }
    }
}, "game")
```

## 环境变量覆盖

Due v2 不对配置项提供通用的 `DUE_{SECTION}_{KEY}` 环境变量覆盖机制，仅内置以下环境变量与运行参数：

| 名称 | 环境变量 | 运行参数 | 说明 |
| --- | --- | --- | --- |
| etc 目录 | `DUE_ETC` | `-etc` | 指定 etc 启动配置目录，默认 `./etc` |
| 运行模式 | `DUE_MODE` | `-mode` | 取值 debug、test、pre-release、release |

```bash
# 指定 etc 目录与运行模式
export DUE_ETC=/path/to/etc
export DUE_MODE=release

./game-server -etc /path/to/etc -mode release
```

> 框架不支持按配置键设置环境变量，敏感信息（如密码）不应通过 `DUE_xxx` 传入，可改用自定义配置源或由程序读取环境变量后通过 `config.Set` 写入。

## 配置最佳实践

### 1. 分离环境配置

将不同环境的 etc 放在不同目录，通过 `DUE_ETC` 环境变量或 `-etc` 运行参数指定：

```
etc/
├── dev/etc.toml          # 开发环境
├── test/etc.toml         # 测试环境
└── prod/etc.toml         # 生产环境
```

**启动时指定环境：**
```bash
# 开发环境
DUE_ETC=./etc/dev ./game-server

# 生产环境
DUE_ETC=./etc/prod ./game-server
```

### 2. 敏感信息处理

框架不支持按配置键设置环境变量，因此敏感信息不应写入配置文件后依赖 `DUE_xxx` 覆盖。可通过自定义配置源（如配置中心）管理，或由程序读取环境变量后写入业务配置：

```go
// 由程序读取环境变量，写入业务配置
if password := os.Getenv("REDIS_PASSWORD"); password != "" {
    _ = config.Set("game.redis.password", password)
}
```

### 3. 配置默认值

```go
// 读取配置时提供默认值
maxLevel := config.Get("game.maxLevel", 100).Int()
timeout := config.Get("game.battle.timeout", 300).Int()
```

### 4. 配置验证

```go
func validateConfig() error {
    maxLevel := config.Get("game.maxLevel", 0).Int()
    if maxLevel <= 0 {
        return errors.New("game.maxLevel 必须大于 0")
    }
    
    expRate := config.Get("game.expRate", 0).Float64()
    if expRate < 0 {
        return errors.New("game.expRate 不能为负数")
    }
    
    return nil
}
```

## 常见问题

### Q1: 配置文件找不到怎么办？

**A:** 确保配置文件在正确的位置：
- 启动配置：`./etc/etc.toml`（默认目录 `./etc`）
- 业务配置：`./config/*.toml`（默认目录 `./config`）

可通过环境变量或运行参数指定 etc 目录：
```bash
export DUE_ETC=/path/to/etc
# 或
./game-server -etc /path/to/etc
```
业务配置路径可通过 etc 配置项 `etc.config.file.path` 或 `file.WithPath` 选项指定。

### Q2: 配置热加载不生效？

**A:** etc 与 config 均由配置文件源加载并监听文件变化，文件被修改后会自动重新加载。业务配置的变更可通过 `config.Watch` 注册回调获得通知；etc 配置未提供 Watch 便捷方法，可通过 `etc.GetConfigurator().Watch(...)` 监听，或再次调用 `etc.Get` 读取最新值。注意 `mode` 仅在程序启动时读取一次，运行期修改不会生效。

### Q3: 如何查看配置项？

**A:** 配置项即配置文件中的内容。etc 启动配置可通过 `etc.Has` / `etc.Get` 按模式读取（如 `etc.Get("etc.packet.routeBytes")`）；业务配置在设置配置器后可通过 `config.Has` / `config.Get` 读取（如 `config.Get("game.maxLevel")`）。框架不会在启动时输出全部配置项。

### Q4: 配置项类型转换失败？

**A:** 确保配置值类型正确：
```toml
# 错误：字符串
maxLevel = "100"

# 正确：整数
maxLevel = 100
```

Due v2 的配置系统灵活强大，通过合理的配置管理，可以轻松适配不同环境，提升开发和运维效率。
