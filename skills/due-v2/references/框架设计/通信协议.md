# 通信协议

## 概述

Due v2 定义了统一的二进制通信协议，包括**心跳帧**、**业务数据帧**和**握手帧**（v2.6.3 新增）三种类型。协议由 `packet` 包实现，支持通过配置调整字节序、路由/序列号字节数、消息体上限以及是否携带服务器心跳时间。

协议设计简洁、无冗余字段，兼顾性能与可扩展性。默认打包器由 `packet.NewPacker()` 创建，全局打包器可以通过 `packet.SetPacker()` 替换（例如实现自定义协议）。

## 协议结构

所有协议包都以固定的 **4 字节 size + 1 字节 header** 开头：

```
| size (4 bytes) | header (1 byte) | payload (可变) |
```

- **size**：4 字节整数，表示 `header + payload` 的字节数，**不包含 size 字段自身的 4 字节**。
- **header**：1 字节标志位，见下。
- **payload**：由帧类型（心跳 / 业务数据 / 握手）决定。

### header 标志位

```
 7   6 5 4 3 2 1 0
+---+-------------+
| H |   extcode   |
+---+-------------+
```

- **H（bit7，0x80）**：心跳标志。`1` = 心跳帧，`0` = 非心跳帧。
- **extcode（bit6~bit0）**：扩展操作码。`0` = 业务数据帧（header `0x00`），`1` = 握手帧（header `0x01`，v2.6.3 新增）。
- 其余位保留。

> **v2.6.3 变更**：删除原 bit6「心跳时间标志」，恢复 `h(1 bit) + extcode(7 bit)` 布局。心跳帧是否携带服务器时间改由 **size** 区分（`size=1` 不带、`size=9` 带 8 字节时间），不再占用标志位。

## 心跳包协议

```
| size (4 bytes) | header (1 byte) | [heartbeat time (8 bytes)] |
```

- **不携带时间**（客户端上行心跳、或未开启 `heartbeatTime`）：
  - `header = 0x80`，`size = 1`，整包固定 **5 字节**。
- **携带时间**（服务器下行心跳，且开启 `heartbeatTime`）：
  - `header = 0x80`，`size = 9`，整包固定 **13 字节**；
  - 后 8 字节为服务器当前时间（`time.Now().UnixNano()`，按配置的字节序编码）；
  - 接收方按 `size` 判断是否读取这 8 字节。

是否携带时间由 `etc.packet.heartbeatTime` 控制，默认 `false`。客户端上行心跳通常不携带时间；服务器收到心跳后按需回带时间，供客户端做时间同步。

### 心跳包示例

```
不携带时间：
┌────────────┬────────┬
│ size=0x00000001 │ header=0x80 │                 → 整包 5 字节
└────────────┴────────┴

服务器携带时间：
┌────────────┬────────┬──────────────────────┐
│ size=0x00000009 │ header=0x80 │ heartbeat time (8B) │   → 整包 13 字节
└────────────┴────────┴──────────────────────┘
```

## 数据包协议

```
| size (4 bytes) | header (1 byte) | route (n bytes) | seq (m bytes) | message (x bytes) |
```

- **header**：数据帧固定为 `0x00`（bit7=0、extcode=0）。
- **route**：路由号，`n` 字节（`n = routeBytes`，取值 1/2/4），有符号整数，服务端据此分发到对应处理器。
- **seq**：序列号，`m` 字节（`m = seqBytes`，取值 0/1/2/4），用于请求-响应配对；`m = 0` 表示不编码序列号。
- **message**：消息体，`x` 字节，`x <= bufferBytes`。
- **size 计算**：`size = 1 + routeBytes + seqBytes + len(message)`。

### 数据包示例

以 `routeBytes = 2`、`seqBytes = 2`、`route = 1`、`seq = 100`、`message = {"action":"move"}`（长度 17）为例：

```
size = 1 + 2 + 2 + 17 = 22 (0x00000016)
┌────────────────┬────────┬────────┬────────┬─────────────────────┐
│ size=0x00000016│  0x00  │ 0x0001 │ 0x0064 │ {"action":"move"}   │
└────────────────┴────────┴────────┴────────┴─────────────────────┘
```

## 握手帧协议（v2.6.3 新增）

```
| size (4 bytes) | header (1 byte) | payload (x bytes) |
```

- **header**：固定 `0x01`（extcode=1）。
- **payload**：会话安全的握手消息（ClientHello / ServerHello / Finished 等）。
- **size 计算**：`size = 1 + len(payload)`；握手帧不带 route/seq，也不占用路由号。
- 网络层通过 `network.Server.OnHandshake` / `network.Client.OnHandshake` 把握手帧交给上层，`packet.ExtractHandshake` 提取 payload。

## 协议配置

在 `etc.toml` 中配置（键前缀 `etc.packet`）：

```toml
[packet]
    # 字节序，可选：little | big。默认为 big
    byteOrder = "big"
    # 路由字节数，可选：1 | 2 | 4。默认为 2
    routeBytes = 2
    # 序列号字节数，可选：0 | 1 | 2 | 4。默认为 2
    seqBytes = 2
    # 消息体最大字节数。默认为 5000
    bufferBytes = 5000
    # 是否携带服务器心跳时间。默认为 false
    heartbeatTime = false
```

对应的代码选项：`packet.WithByteOrder` / `packet.WithRouteBytes` / `packet.WithSeqBytes` / `packet.WithBufferBytes` / `packet.WithHeartbeatTime`。

route 与 seq 均按**有符号整数**编码，取值范围：

- `routeBytes = 1`：-128 ~ 127
- `routeBytes = 2`：-32768 ~ 32767
- `routeBytes = 4`：int32 范围

业务上通常只使用正整数路由号。打包时的边界校验错误：

- route 越界：`errors.ErrRouteOverflow`
- seq 越界：`errors.ErrSeqOverflow`
- message 超过 `bufferBytes`：`errors.ErrMessageTooLarge`

## 协议处理流程

### 发送

1. 序列化业务数据为 message。
2. 计算 `size = 1 + routeBytes + seqBytes + len(message)`。
3. 依次写入 `size`、`header(0x00)`、`route`、`seq`、`message`。
4. 发送到对端。

### 接收

1. 读取 4 字节 `size`。
2. 读取 1 字节 `header`：
   - bit7 置位：心跳帧。`size=1` 读取完成；`size=9` 再读 8 字节服务器时间。
   - extcode=1：握手帧，读取 `size-1` 字节 payload，交给 `OnHandshake`。
   - 其余：业务数据帧，按 `size-1` 读取 `route` / `seq` / `message`。
3. 业务帧解析 `route` / `seq`。
4. 将 message 交给业务层处理。

### 关键 API（packet 包，v2.6.3 起 Breaking Change）

```go
// FrameType 帧类型枚举（v2.6.3 新增，取代旧的 bool 返回值）
type FrameType uint8
const (
    FrameData      FrameType = iota // 业务数据帧（0）
    FrameHeartbeat                  // 心跳帧（1）
    FrameHandshake                  // 握手帧（2，v2.6.3 新增）
)

// Packer 打包器接口
type Packer interface {
    // Read 从 reader 读下一帧；返回帧类型、服务器心跳时间（仅心跳帧有意义，纳秒）、帧缓冲
    // v2.6.3 Breaking Change：原 (bool, int64, Buffer, error) → (FrameType, int64, Buffer, error)
    Read(reader io.Reader) (FrameType, int64, buffer.Buffer, error)

    // PackMessage 打包业务数据帧
    // v2.6.3 Breaking Change：原 PackMessage(message *Message) → PackMessage(route, seq int32, data []byte)
    // packet.Message 类型已整体移除
    PackMessage(route, seq int32, data []byte) (buffer.Buffer, error)

    // PackHandshake 打包握手帧（v2.6.3 新增，不带 route/seq）
    PackHandshake(payload []byte) (buffer.Buffer, error)

    // PackHeartbeat 打包心跳帧；server=true 时可携带服务器侧时间
    PackHeartbeat(server ...bool) buffer.Buffer

    // UnpackMessage 解包业务数据帧，返回 route、seq、payload
    UnpackMessage(buf buffer.Buffer) (int32, int32, buffer.Buffer, error)

    // ExtractHandshake 从握手帧中提取 payload（v2.6.3 新增）
    ExtractHandshake(buf buffer.Buffer) ([]byte, error)

    // ExtractRouteSeq 从业务帧中提取 route / seq（v2.6.3 起仍保留）
    ExtractRouteSeq(buf buffer.Buffer) (int32, int32, error)
}
```

> **v2.6.3 Breaking Changes**:
> 1. `packet.Message` 类型整体移除，`PackMessage` 参数改为 `(route, seq int32, data []byte)`
> 2. `Read` 第一返回值从 `bool`（是否心跳）改为 `FrameType` 枚举
> 3. 新增 `PackHandshake` / `ExtractHandshake` 支持独立握手帧
> 4. header 布局调整：删除 bit6 心跳时间位，握手帧使用 extcode=1；心跳时间改由 size 区分
> 5. `ExtractRouteSeq` 仍保留，用于业务帧的 route/seq 提取
> 6. `network.Server` / `network.Client` 接口新增必需方法 `OnHandshake(handler HandshakeHandler)`，自定义实现必须补上

> `PackHeartbeat` 在不携带时间时返回的是一个**共享的预构建缓冲**，调用方不得修改或释放它。

## 零拷贝打包 API（v2.6.3 ~ v2.6.5）

```go
// v2.6.5：读帧时预留的 headroom（字节，固定 32），传输层可原地预置自己的头
func ReadBufferHeadroom() int

// v2.6.3：打包池化 payload；成功时所有权转移给返回的 buffer，失败时调用方仍持有 payload
// 需要 packer 实现 MessageBufferPacker；不支持时内部会退化为复制
func PackMessageBuffer(route, seq int32, payload *buffer.Bytes) (buffer.Buffer, error)

// v2.6.3：当前 packer 能为池化 payload 预留的头部空间；0 表示不支持原地预置
func MessageBufferHeadroom() int

// v2.6.3：不修改 buffer 地提取 route / seq / payload；payload 可能引用 buf，buf 释放后不可再用
func ExtractMessage(buf buffer.Buffer) (route int32, seq int32, payload []byte, err error)

// v2.6.5：Bytes.Resize 设置可读长度并保留 headroom，越界返回 false（配合 Appender）
func (b *Bytes) Resize(size int) bool
```

配套的 `encoding.Appender` 接口（json/proto/msgpack 均已实现）允许 codec 把编码结果追加到调用方缓冲：

```go
type Appender interface {
    // 把 v 的编码追加到 dst；必要时会重新分配 dst，调用方通过返回切片判断
    Append(dst []byte, v any) ([]byte, error)
}
```

## 最佳实践

### 1. 合理配置协议参数

```toml
# 小型游戏：减少开销
[packet]
    routeBytes = 1      # 路由号范围 -128 ~ 127
    seqBytes = 2
    bufferBytes = 2000

# 大型游戏：支持更多路由
[packet]
    routeBytes = 2
    seqBytes = 4
    bufferBytes = 10000
```

### 2. 心跳检测策略

心跳检测由网络层负责，可配置检测间隔与心跳机制（`resp`：被动响应式；`tick`：主动定时下发）：

```toml
[network.tcp.server]
    # 心跳检测间隔，默认 10s
    heartbeatInterval = "10s"
    # 心跳机制，可选：resp | tick，默认 resp
    heartbeatMechanism = "resp"
```

客户端应按照约定的时间间隔发送心跳包（协议格式见上文），具体的网络层细节请参考 [网络通信](../核心模块/网络通信.md)。

### 3. 大包拆分

当消息体超过 `bufferBytes` 时，`PackMessage` 返回 `errors.ErrMessageTooLarge`。业务层应将大消息拆分为多个小包发送与组装。

### 4. 序列号管理

- `seqBytes > 0`：启用序列号，适用于请求-响应模式，用 seq 做配对。
- `seqBytes = 0`：不编码序列号，适用于单向通知，可进一步减小包体。

## 常见问题

### Q1：为什么默认不携带心跳时间？

**A：** 默认不携带是为了减少网络开销。如果客户端需要时间同步，可将 `etc.packet.heartbeatTime` 设为 `true`。

### Q2：`size` 是否包含其自身的 4 字节？

**A：** 不包含。`size = 1 + routeBytes + seqBytes + len(message)`，即只统计 header 与 payload。

### Q3：如何修改字节序？

**A：** 通过 `etc.packet.byteOrder` 设置为 `little` 或 `big`（默认 `big`）。大端序是网络字节序的标准。

### Q4：如何支持自定义协议？

**A：** 实现 `packet.Packer` 接口，并通过 `packet.SetPacker()` 替换全局打包器即可。

## 版本更新摘要

### v2.6.5

**新特性 / 性能**：
- 新增 `ReadBufferHeadroom`（固定 32 字节）与 `core/buffer.Bytes.Resize`；deliver / push 传输头原地预置
- 配合 `encoding.Appender` 实现原地编码，1KB 消息 0 alloc
- 安全消息路径（密文下行、明文上行）保持单节点帧，减少拷贝

### v2.6.3

**Breaking Changes**：
- `Packer.Read` 返回 `FrameType`；`packet.Message` 删除，`PackMessage` 改标量参数
- 新增 `PackHandshake` / `ExtractHandshake` 与 `FrameHandshake`；`network` 新增 `OnHandshake`
- header 删除 bit6 心跳时间位；握手帧 `header=0x01`；心跳时间由 size 区分
- 新增 `PackMessageBuffer` / `ExtractMessage` / `MessageBufferHeadroom`；`ExtractRouteSeq` 保留

## 总结

Due v2 的通信协议通过固定头部 + 可配置的 route/seq/message 结构，配合灵活的打包配置，适应不同规模与场景的需求。理解协议格式与 `packet` 包 API，是开发高性能游戏服务器的基础。
