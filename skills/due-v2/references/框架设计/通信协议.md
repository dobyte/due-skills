# 通信协议

## 概述

Due v2 定义了统一的二进制通信协议，包括**心跳包**和**数据包**两种类型。协议由 `packet` 包实现，支持通过配置调整字节序、路由/序列号字节数、消息体上限以及是否携带服务器心跳时间。

协议设计简洁、无冗余字段，兼顾性能与可扩展性。默认打包器由 `packet.NewPacker()` 创建，全局打包器可以通过 `packet.SetPacker()` 替换（例如实现自定义协议）。

## 协议结构

所有协议包都以固定的 **4 字节 size + 1 字节 header** 开头：

```
| size (4 bytes) | header (1 byte) | payload (可变) |
```

- **size**：4 字节整数，表示 `header + payload` 的字节数，**不包含 size 字段自身的 4 字节**。
- **header**：1 字节标志位，见下。
- **payload**：由包类型（心跳包 / 数据包）决定。

### header 标志位

```
 7   6   5 4 3 2 1 0
+---+---+-----------+
| H | T |  reserved |
+---+---+-----------+
```

- **H（bit7，0x80）**：心跳标志。`1` = 心跳包，`0` = 数据包。
- **T（bit6，0x40）**：心跳时间标志。仅当为心跳包时有效；`1` 表示随后携带 8 字节服务器时间。
- 其余位保留。

> 注意：header 只有这两个有效标志位，**不存在 7 位的扩展操作码（extcode）**。

## 心跳包协议

```
| size (4 bytes) | header (1 byte) | [heartbeat time (8 bytes)] |
```

- **不携带时间**（客户端上行心跳、或未开启 `heartbeatTime`）：
  - `header = 0x80`，`size = 1`，整包固定 **5 字节**。
- **携带时间**（服务器下行心跳，且开启 `heartbeatTime`）：
  - `header = 0xC0`，`size = 9`，整包固定 **13 字节**；
  - 后 8 字节为服务器当前时间（`time.Now().UnixNano()`，按配置的字节序编码）。

是否携带时间由 `etc.packet.heartbeatTime` 控制，默认 `false`。客户端上行心跳通常不携带时间；服务器收到心跳后按需回带时间，供客户端做时间同步。

### 心跳包示例

```
不携带时间：
┌────────────┬────────┬
│ size=0x00000001 │ header=0x80 │                 → 整包 5 字节
└────────────┴────────┴

服务器携带时间：
┌────────────┬────────┬──────────────────────┐
│ size=0x00000009 │ header=0xC0 │ heartbeat time (8B) │   → 整包 13 字节
└────────────┴────────┴──────────────────────┘
```

## 数据包协议

```
| size (4 bytes) | header (1 byte) | route (n bytes) | seq (m bytes) | message (x bytes) |
```

- **header**：数据包固定为 `0x00`。
- **route**：路由号，`n` 字节（`n = routeBytes`，取值 1/2/4），有符号整数，服务端据此分发到对应处理器。
- **seq**：序列号，`m` 字节（`m = seqBytes`，取值 0/1/2/4），用于请求-响应配对；`m = 0` 表示不编码序列号。
- **message**：消息体，`x` 字节，`x <= bufferBytes`。
- **size 计算**：`size = 1 + routeBytes + seqBytes + len(message)`。

### 数据包示例

以 `routeBytes = 2`、`seqBytes = 2`、`route = 1`、`seq = 100`、`message = {"action":"move"}`（长度 17）为例：

```
size = 1 + 2 + 2 + 17 = 22 (0x00000016)
┌────────────────┬────────┬────────┬────────┬─────────────────────┐
│ size=0x00000016│  0x00  │ 0x0001 │ 0x0064 │ {"action":"move"}   │
└────────────────┴────────┴────────┴────────┴─────────────────────┘
```

## 协议配置

在 `etc.toml` 中配置（键前缀 `etc.packet`）：

```toml
[packet]
    # 字节序，可选：little | big。默认为 big
    byteOrder = "big"
    # 路由字节数，可选：1 | 2 | 4。默认为 2
    routeBytes = 2
    # 序列号字节数，可选：0 | 1 | 2 | 4。默认为 2
    seqBytes = 2
    # 消息体最大字节数。默认为 5000
    bufferBytes = 5000
    # 是否携带服务器心跳时间。默认为 false
    heartbeatTime = false
```

对应的代码选项：`packet.WithByteOrder` / `packet.WithRouteBytes` / `packet.WithSeqBytes` / `packet.WithBufferBytes` / `packet.WithHeartbeatTime`。

route 与 seq 均按**有符号整数**编码，取值范围：

- `routeBytes = 1`：-128 ~ 127
- `routeBytes = 2`：-32768 ~ 32767
- `routeBytes = 4`：int32 范围

业务上通常只使用正整数路由号。打包时的边界校验错误：

- route 越界：`errors.ErrRouteOverflow`
- seq 越界：`errors.ErrSeqOverflow`
- message 超过 `bufferBytes`：`errors.ErrMessageTooLarge`

## 协议处理流程

### 发送

1. 序列化业务数据为 message。
2. 计算 `size = 1 + routeBytes + seqBytes + len(message)`。
3. 依次写入 `size`、`header(0x00)`、`route`、`seq`、`message`。
4. 发送到对端。

### 接收

1. 读取 4 字节 `size`。
2. 读取 1 字节 `header`，判断 bit7：
   - 为心跳：若 bit6 置位则再读 8 字节时间，否则读取完成。
   - 为数据：按 `size` 读取剩余部分。
3. 解析 `route` / `seq`。
4. 将 message 交给业务层处理。

### 关键 API（packet 包）

```go
// 读取一个包：是否为心跳、服务器心跳时间（纳秒）、消息缓冲、错误
Read(reader io.Reader) (bool, int64, buffer.Buffer, error)

// 打包消息
PackMessage(message *Message) (buffer.Buffer, error)

// 解包消息：路由号、序列号、消息缓冲、错误
UnpackMessage(buf buffer.Buffer) (route, seq int32, message buffer.Buffer, err error)

// 仅提取路由号与序列号
ExtractRouteSeq(buf buffer.Buffer) (route, seq int32, err error)

// 打包心跳包；server 为 true 时打包服务器侧心跳（可携带时间）
PackHeartbeat(server ...bool) buffer.Buffer
```

> `PackHeartbeat` 在不携带时间时返回的是一个**共享的预构建缓冲**，调用方不得修改或释放它。

## 最佳实践

### 1. 合理配置协议参数

```toml
# 小型游戏：减少开销
[packet]
    routeBytes = 1      # 路由号范围 -128 ~ 127
    seqBytes = 2
    bufferBytes = 2000

# 大型游戏：支持更多路由
[packet]
    routeBytes = 2
    seqBytes = 4
    bufferBytes = 10000
```

### 2. 心跳检测策略

心跳检测由网络层负责，可配置检测间隔与心跳机制（`resp`：被动响应式；`tick`：主动定时下发）：

```toml
[network.tcp.server]
    # 心跳检测间隔，默认 10s
    heartbeatInterval = "10s"
    # 心跳机制，可选：resp | tick，默认 resp
    heartbeatMechanism = "resp"
```

客户端应按照约定的时间间隔发送心跳包（协议格式见上文），具体的网络层细节请参考 [网络通信](../核心模块/网络通信.md)。

### 3. 大包拆分

当消息体超过 `bufferBytes` 时，`PackMessage` 返回 `errors.ErrMessageTooLarge`。业务层应将大消息拆分为多个小包发送与组装。

### 4. 序列号管理

- `seqBytes > 0`：启用序列号，适用于请求-响应模式，用 seq 做配对。
- `seqBytes = 0`：不编码序列号，适用于单向通知，可进一步减小包体。

## 常见问题

### Q1：为什么默认不携带心跳时间？

**A：** 默认不携带是为了减少网络开销。如果客户端需要时间同步，可将 `etc.packet.heartbeatTime` 设为 `true`。

### Q2：`size` 是否包含其自身的 4 字节？

**A：** 不包含。`size = 1 + routeBytes + seqBytes + len(message)`，即只统计 header 与 payload。

### Q3：如何修改字节序？

**A：** 通过 `etc.packet.byteOrder` 设置为 `little` 或 `big`（默认 `big`）。大端序是网络字节序的标准。

### Q4：如何支持自定义协议？

**A：** 实现 `packet.Packer` 接口，并通过 `packet.SetPacker()` 替换全局打包器即可。

## 总结

Due v2 的通信协议通过固定头部 + 可配置的 route/seq/message 结构，配合灵活的打包配置，适应不同规模与场景的需求。理解协议格式与 `packet` 包 API，是开发高性能游戏服务器的基础。
