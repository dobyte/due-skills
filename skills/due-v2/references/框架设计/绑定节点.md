# 绑定节点

## 概述

绑定节点（Bind Node）是将用户（UID）与特定节点服建立关联的过程。绑定后，该用户的所有有状态路由消息都会被路由到绑定的节点服处理。这是实现有状态服务的基础。

## 核心概念

### 为什么需要绑定节点

```
场景：MMORPG 游戏

玩家 A 登录到节点服 1
    ↓
玩家 A 的游戏数据（角色、背包、位置）加载到节点服 1 的内存中
    ↓
玩家 A 发送移动消息
    ↓
消息必须路由到节点服 1（因为只有节点服 1 有玩家 A 的内存数据）
    ↓
如果路由到节点服 2，节点服 2 没有玩家 A 的数据，无法处理
```

### 绑定信息

绑定信息存储在 Redis 中，由一个哈希键保存“节点名 → 节点实例 ID”的映射：

```
{prefix}:locate:user:{uid}:node   # 哈希键：field 为节点名，value 为节点实例 ID（NID），prefix 默认为 due:locate
```

同一个用户可以绑定多个节点服（不同节点名各一条），但每个节点名只能绑定一个节点服；以相同节点名再次绑定会覆盖先前的绑定。

## 绑定流程

### 完整流程

```
1. 用户登录，绑定网关（BindGate）
   ↓
2. 节点服加载用户数据到内存
   ↓
3. 节点服调用 ctx.BindNode(uid)
   ↓
4. 绑定信息写入 Redis：哈希键 {prefix}:locate:user:{uid}:node 的“节点名 → NID”字段
   ↓
5. 绑定事件通过发布订阅广播给网关服与相关节点服，各端更新本地用户源缓存
   ↓
6. 后续有状态路由消息根据绑定信息路由到该节点服
```

### 代码示例

```go
// 登录处理器
func loginHandler(ctx node.Context) {
    req := &loginReq{}
    if err := ctx.Parse(req); err != nil {
        ctx.Response(&loginRes{Code: 400})
        return
    }
    
    // 1. 验证账号密码
    uid, err := verifyUser(req.Account, req.Password)
    if err != nil {
        ctx.Response(&loginRes{Code: 401})
        return
    }
    
    // 2. 绑定网关
    if err := ctx.BindGate(uid); err != nil {
        ctx.Response(&loginRes{Code: 500})
        return
    }
    
    // 3. 绑定节点（关键步骤）
    if err := ctx.BindNode(uid); err != nil {
        ctx.UnbindGate(uid)
        ctx.Response(&loginRes{Code: 500})
        return
    }
    
    // 4. 加载玩家数据到内存
    player, err := loadPlayerData(uid)
    if err != nil {
        ctx.UnbindNode(uid)
        ctx.UnbindGate(uid)
        ctx.Response(&loginRes{Code: 500})
        return
    }
    
    // 5. 将玩家对象存入内存
    playerManager.AddPlayer(uid, player)
    
    ctx.Response(&loginRes{Code: 0, UID: uid})
}
```

## 绑定机制详解

### BindNode 方法

```go
// 方法签名（node.Context 接口）
BindNode(uid ...int64) error
```

**参数：**
- `uid`（可选）：用户 ID。不传时使用当前上下文已关联的 UID。

**返回值：**
- `error`：绑定失败时返回错误；当未携带 UID 时返回 `errors.ErrIllegalOperation`。

**调用链：**

```
ctx.BindNode(uid)                         // request / event 实现
  → node.Proxy.BindNode(ctx, uid)         // 未显式指定时，节点名与实例 ID 取当前节点
    → NodeLinker.BindNode(ctx, uid, name, nid)
      → Locator.BindNode(ctx, uid, name, nid)  // Redis：HSET {prefix}:locate:user:{uid}:node name -> nid
      → 更新本地用户源缓存
      → 通过发布订阅广播 BindNode 事件给网关服与相关节点服
```

`Proxy.BindNode` 还支持显式指定节点名与实例 ID：`proxy.BindNode(ctx, uid, name, nid)`（`nameAndNID` 为可变参数）。

### 消息路由机制

#### 有状态路由

```
客户端发送消息（route=10, UID=1001）
    ↓
路由被注册为有状态路由（StatefulRoute）
    ↓
按路由分组（节点名）查询绑定信息：UID=1001, name → Node-1
    ↓
网关服将消息转发到 Node-1
    ↓
Node-1 处理消息（可以访问内存中的玩家数据）
```

#### 无状态路由

```
客户端发送消息（route=1, UID=1001）
    ↓
网关服检查路由类型：无状态路由
    ↓
网关服忽略绑定信息，按分发策略选择节点服
    ↓
消息可能路由到 Node-1、Node-2 或 Node-3
    ↓
节点服处理消息（不能访问内存数据，需从数据库/缓存读取）
```

## 解绑节点

### 关于自动解绑

框架不会在节点服关闭时自动解绑用户与该节点的绑定关系，定位器中的 UID→NID 记录会保留：

- 正常情况下应在用户登出等时机由业务主动调用 `ctx.UnbindNode(uid)`；
- 若节点服异常宕机，遗留的绑定记录需要由业务侧清理，或在其重连/重新绑定时被覆盖。

绑定与解绑事件都会通过发布订阅广播，使网关服与相关节点服同步更新本地用户源缓存。

### 手动解绑

用户登出时，主动解绑：

```go
// 登出处理器
func logoutHandler(ctx node.Context) {
    uid := ctx.UID()
    
    // 1. 保存玩家数据到数据库
    player := playerManager.GetPlayer(uid)
    if player != nil {
        savePlayerData(player)
    }
    
    // 2. 从内存中移除玩家对象
    playerManager.RemovePlayer(uid)
    
    // 3. 解绑节点
    ctx.UnbindNode(uid)
    
    // 4. 解绑网关
    ctx.UnbindGate(uid)
    
    ctx.Response(&logoutRes{Code: 0})
}
```

## 跨节点通信

### 场景：玩家 A 攻击玩家 B

```
玩家 A（绑定在 Node-1）攻击玩家 B（绑定在 Node-2）
    ↓
Node-1 处理攻击逻辑
    ↓
Node-1 需要通知 Node-2 扣除玩家 B 的血量
    ↓
Node-1 通过 RPC 调用 Node-2
    ↓
Node-2 扣除玩家 B 血量并广播伤害信息
```

### 代码示例

```go
// 应用伤害的路由号（需在目标节点注册为有状态路由）
const applyDamage = 100

// Node-1：攻击处理器
func attackHandler(ctx node.Context) {
    attackerUID := ctx.UID()
    req := &attackReq{}
    if err := ctx.Parse(req); err != nil {
        return
    }

    targetUID := req.TargetUID
    proxy := ctx.Proxy()

    // 1. 查询目标玩家所在节点（按当前节点名查询）
    nid, err := proxy.LocateNode(ctx.Context(), targetUID, proxy.GetName())
    if err != nil {
        ctx.Response(&attackRes{Code: 404, Message: "目标玩家不存在"})
        return
    }

    // 2. 计算伤害
    attacker := playerManager.GetPlayer(attackerUID)
    damage := calculateDamage(attacker)

    // 3. 分发处理
    if nid != proxy.GetID() {
        // 跨节点投递：消息会交由目标节点的 applyDamage 路由处理
        err = proxy.Deliver(ctx.Context(), &cluster.DeliverArgs{
            NID: nid,
            UID: targetUID,
            Message: &cluster.Message{
                Route: applyDamage,
                Data:  &damageData{TargetUID: targetUID, Damage: damage},
            },
        })
        if err != nil {
            ctx.Response(&attackRes{Code: 500, Message: "攻击失败"})
            return
        }
    } else {
        // 同节点处理
        applyDamageToPlayer(targetUID, damage)
    }

    ctx.Response(&attackRes{Code: 0, Damage: damage})
}

// Node-2：在目标节点注册 applyDamage 有状态路由
proxy.AddRouteHandler(applyDamage, applyDamageHandler, node.StatefulRoute)

// 应用伤害
func applyDamageHandler(ctx node.Context) {
    req := &damageData{}
    if err := ctx.Parse(req); err != nil {
        return
    }

    applyDamageToPlayer(req.TargetUID, req.Damage)
}
```

> 说明：`Proxy.Deliver` 在 `NID` 等于当前节点时会返回 `errors.ErrIllegalOperation`，因此同节点场景需要直接本地处理，不能调用 `Deliver`。目标节点须将该路由注册为有状态路由（`StatefulRoute`），否则投递时无法通过用户归属校验。

## 负载均衡与绑定

### 无状态路由的负载均衡

登录等无状态路由消息由分发策略（`cluster.gate.dispatch`：`random` | `rr` | `wrr`）选择节点服，其中 `wrr` 依据节点权重 `cluster.node.weight` 进行加权轮询。因此由哪个节点服接收登录请求、并由该节点执行 `BindNode`，取决于分发策略与权重配置。

### 查看可用节点服

可通过代理获取节点服列表：

```go
instances, err := ctx.Proxy().FetchNodeList(ctx.Context(), cluster.Work)
if err != nil {
    log.Errorf("get node list failed: %v", err)
    return
}

for _, ins := range instances {
    log.Printf("node id: %s, name: %s, state: %s", ins.ID, ins.Alias, ins.State)
}
```

框架不提供“按负载选择节点并转发绑定请求”的内置能力，用户最终绑定到哪个节点由处理登录请求的节点自身决定。

## 最佳实践

### 1. 绑定前检查

```go
func bindUser(ctx node.Context, uid int64) error {
    proxy := ctx.Proxy()

    // 检查用户是否已绑定到其他节点
    nid, err := proxy.LocateNode(ctx.Context(), uid, proxy.GetName())
    if err == nil && nid != "" && nid != proxy.GetID() {
        log.Warnf("用户 %d 已绑定到节点 %s，先解绑", uid, nid)
        if err = proxy.UnbindNode(ctx.Context(), uid); err != nil {
            return err
        }
    }

    return ctx.BindNode(uid)
}
```

### 2. 绑定后加载数据

```go
func loginHandler(ctx node.Context) {
    uid := ctx.UID()
    
    // 绑定节点
    ctx.BindNode(uid)
    
    // 立即加载数据到内存
    player, err := loadPlayerFromDB(uid)
    if err != nil {
        ctx.UnbindNode(uid)
        return
    }
    
    playerManager.AddPlayer(uid, player)
}
```

### 3. 定期保存数据

```go
// 每 5 分钟保存一次所有玩家数据
func startAutoSave() {
    ticker := time.NewTicker(5 * time.Minute)
    go func() {
        for range ticker.C {
            for _, player := range playerManager.GetAllPlayers() {
                savePlayerToDB(player)
            }
        }
    }()
}
```

### 4. 节点服优雅关闭

```go
// 通过监听 Close 钩子，在节点关闭时保存数据
proxy.AddHookListener(cluster.Close, func(proxy *node.Proxy) {
    log.Info("节点服准备关闭，保存所有玩家数据...")

    for _, player := range playerManager.GetAllPlayers() {
        savePlayerToDB(player)
    }

    log.Info("节点服关闭完成")
})
```

## 常见问题

### Q1: 绑定节点后可以更换节点吗？

**A:** 可以，但需要：
1. 保存当前节点的数据
2. 解绑当前节点
3. 绑定到新节点
4. 在新节点加载数据

这通常用于节点服负载均衡或故障转移。

### Q2: 节点服宕机，绑定的用户怎么办？

**A:** 
- 绑定信息仍存在于 Redis 中
- 用户需要重新登录，绑定到新的节点服
- 建议实现自动重连机制

### Q3: 如何实现跨服战斗？

**A:** 跨服战斗可以：
1. 将所有参战玩家绑定到同一个节点服（战斗服）
2. 通过节点代理的 `Deliver` 投递到有状态路由处理，或使用网格服务（`Proxy.NewMeshClient`）实现跨节点通信
3. 使用 Actor 模型管理战斗房间

### Q4: 绑定信息会过期吗？

**A:** 定位器写入绑定记录时不设置过期时间（键无 TTL），绑定信息不会自动过期。若节点服异常宕机，遗留的绑定记录需要由业务侧清理，或在其重连/重新绑定时被覆盖。

## 总结

绑定节点是实现有状态服务的核心机制，通过将用户与节点服关联，确保消息路由的正确性。合理使用绑定机制，可以构建高性能、可扩展的游戏服务器。
