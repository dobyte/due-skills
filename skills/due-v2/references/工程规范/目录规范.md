# 目录规范

## 1. 完整骨架

```
<repo>/
├── go.mod / go.sum
├── build.sh                      # 单服务构建与发布（宿主机编译 + 运行时打包）
├── scripts/init-deps.sh          # 依赖版本解析（拉取最新）
├── scripts/gen-etc.sh            # 按角色生成各服务 etc.toml（取自框架最新版模板）
├── protoc.sh                     # 统一协议生成（全部 .proto）
├── internal/                     # 跨服务共享内核
│   ├── code/                     # 统一错误码
│   ├── protocol/                 # .proto 源 + 生成物
│   │   ├── base.proto            # 通用响应等
│   │   ├── common.proto          # 错误码枚举 + 公共消息
│   │   ├── <domain>.proto        # 各模块路由号 + 消息
│   │   └── <domain>/<domain>.pb.go
│   ├── define/                   # 常量（路由号段登记在此）
│   ├── component/<x>/            # 公共组件单例
│   ├── event/<domain>/           # 事件 topic 与载荷
│   ├── model/                    # 数据模型
│   ├── dao/<domain>/             # 数据访问（生成）
│   ├── service/<domain>/
│   │   ├── pb/<domain>.mesh.svc.proto + 生成物
│   │   ├── server/server.go      # 注册服务提供者
│   │   └── client/client.go      # discovery://<domain>
│   ├── middleware/               # 中间件
│   ├── share/etc/                # 共享配置（<project>.<env>.toml，构建期分发）
│   └── helper/ | library/ | utils/
├── gate/     {main.go, etc/etc.toml, Dockerfile}
├── hall/     {main.go, app/app.go, app/logic/, etc/, Dockerfile}
├── mesh/     {main.go, app/app.go, etc/, Dockerfile}
├── web/      {main.go, app/app.go, app/api/, etc/, Dockerfile}
├── database/ # DDL
└── docker/   # 本地编排（可选）
```

## 2. 三条硬约定

1. **服务目录同构**：`main.go` + `app/app.go` + `etc/etc.toml` + `Dockerfile`；需要 Helm 再加 `chart/`。
   - 网关是纯连接层，**可无 `app/` 层**，`main.go` 装配即止。
   - `Dockerfile` 为**运行时打包式**（`FROM <基础镜像>` + `COPY main` + `ARG ENV`），镜像内不装 Go 工具链；详见 [构建与交付](构建与交付.md)。
2. **`main.go` 只做装配**：装配代码留在**本服务内**，不抽公共骨架；应用的 `app.Init(proxy)` **只做装配，不写业务逻辑**。
3. **常量集中**：路由号与协议相关常量放 `route` 或 `define` 包，禁止散落在各业务文件。

## 3. app/ 内部划分

| 子目录 | 用途 | 适用服务 |
| --- | --- | --- |
| `app/logic/` | 路由注册与业务处理（Node） | `hall`、`game-*`、`activity` |
| `app/api/` | HTTP 接口（按模块分子目录） | `web`、`admin` |
| `app/limiter/` | 限流器（可选） | HTTP 服务 |

`app/app.go` 提供唯一的 `Init(proxy)`，逐层调用各子模块的 `Init()`，自身不实现业务。

## 4. 数据层

- 模型放 `internal/model/`，一表一文件；表名用 `TableName()` 显式声明。
- DAO 放 `internal/dao/<domain>/`，**由生成器产出，禁止手写**。
- DDL 放 `database/*.sql`，表结构变更须同步模型与 changelog。

## 5. 新增服务时要动的地方

- [ ] 新建服务目录，套用同构最小集（`main.go` + `app/` + `etc/` + `Dockerfile`）
- [ ] `main.go` 按同类服务结构直接装配（`due.NewContainer()` → 设施与组件 → `app.Init` → `Serve`）
- [ ] 若涉及新路由号段，先在 `define` 登记，再写协议
- [ ] 补 `Dockerfile`（运行时打包式）与共享配置（`internal/share/etc/` 下按环境补文件）
- [ ] 补部署配置（Helm `chart/`）与构建发布链路

## 6. 反模式

- 各服务装配结构不统一（应复制同类服务的 `main.go` 结构，保持一致）。
- 业务逻辑写进 `internal/`（内核不该有业务）。
- 手写 DAO 或绕过 DAO 拼 SQL。
- 每服务目录结构各不相同，难以复用模板。
- 生成物（`*.pb.go`）与手写文件混放、被手工编辑。
