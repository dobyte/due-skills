# 协议规范

## 1. proto 组织

| 文件 | 内容 |
| --- | --- |
| `base.proto` | 通用响应（内嵌错误码） |
| `common.proto` | 错误码枚举 + 跨模块复用的公共消息 |
| `<domain>.proto` | 某模块的路由号枚举 + 该模块请求/响应消息 |
| `<domain>.mesh.svc.proto` | 微服务接口（service + args/reply），放在 `internal/service/<domain>/pb/` |

约定：

- 每个 proto 显式声明 `option go_package`，指向 `<module>/internal/...`。
- 响应消息**内嵌通用错误响应**作为第 1 个字段，客户端据此统一判错。
- 请求 / 响应**成对**：`XxxReq` / `XxxRes`。

## 2. 生成流程

- **源为 `.proto`**，用仓库根的统一脚本生成，覆盖客户端协议与微服务协议两类。
- **禁止手改生成物**（`*.pb.go` / `*_grpc.pb.go`）；改协议必须改 `.proto` 再重新生成。
- 生成脚本需带 `module=<module>` 选项，避免生成物目录多一层前缀。

## 3. 路由号段

路由号是消息在集群中的流转标识，**先规划、后使用，禁止复用**：

| 区间 | 归属 |
| --- | --- |
| `[1000,1999]` | 大厅 |
| `[2000,2999]` | 活动 |
| `[3000,3999]` | 通知 |
| 自 `10000` 起，每个子游戏独占 `1000` | 子游戏 |

- 新模块先到 `define` 登记号段，再落 `.proto`。
- 路由号集中在 `<domain>.proto` 的 `enum Route` 中定义，业务代码引用枚举，禁止裸写数字。

> **适用范围**：本规范针对**正式项目**。`examples/` 下的最小示例为便于阅读，直接用 `const greet = 1` 之类的裸路由号，仅作演示、**不作为项目模板**；正式项目必须按上方号段规划，并在 `define` / `enum Route` 登记。

## 4. 路由选项

注册路由时按语义选择选项（**不要凭记忆写，先看最新版源码**）：

| 选项 | 语义 | 适用 |
| --- | --- | --- |
| 默认（无选项） | 无状态，可分发到任意节点 | 登录、拉取、查询 |
| `StatefulRoute` | 有状态，固定路由到绑定节点 | 牌桌、房间、战斗 |
| `AuthorizedRoute` | 流转时必须携带 UID | 需登录态的业务 |
| `InternalRoute` | 仅在节点间流转 | 节点间内部消息 |

- 默认即无状态；**不存在** `StatelessRoute` 之类的选项名，写之前先核对源码。
- 中间件既可挂路由组（`group.Middleware(...)`），也可随路由选项携带（`RouteOptions.Middlewares`）。
- 有状态处理必须落到 Actor（单协程串行），**禁止**在中间件或路由入口做阻塞 IO / 长耗时计算。

## 5. 错误码

- 基础错误码用框架内置；业务错误码**先在 `common.proto` 登记**，再在 `internal/code` 包装成中文码。
- 业务代码只引用包装后的码对象，**禁止硬编码数字**。
- 新增错误码即改协议，须走生成流程。

## 6. 兼容规则

- 字段**只增不改**：不改 tag、不改字段序号、不改类型。
- 废弃字段保留序号（可改注释标注废弃），不得挪作他用。
- 枚举新增值追加在末尾，不占用已废弃值的编号。

## 7. 反模式

- 手改生成物，或 `.proto` 与生成物不一致。
- 路由号裸写数字、跨模块复用号段。
- 声称使用 `StatelessRoute` 等不存在的选项名。
- 在路由入口 / 中间件里做阻塞等待、跨服务同步调用。
- 复用废弃字段序号。
