# 配置规范（etc.toml）

## 1. 动态生成，不手写

各服务的 `etc/etc.toml` **由脚本从框架最新版自带的配置模板动态生成**，禁止手写——手写必然滞后于框架版本，且容易漏项/漏注释。

> **适用范围**：本规范针对**正式项目**。`examples/` 下的最小示例为便于阅读，采用**手写精简配置**（只保留该示例实际用到的 section，如 `quick-start` 省去了 `taskQueueSize`/`linker` 等），仅作演示、**不作为项目模板**；正式项目一律走 `gen-etc.sh` 生成。

```bash
bash scripts/init-deps.sh     # 先拉取最新依赖（决定模板版本）
bash scripts/gen-etc.sh       # 再按角色生成各服务 etc.toml（默认 gate hall mesh web）
```

`gen-etc.sh` 的工作方式：

1. `go list -m -f '{{.Dir}}' github.com/dobyte/due/v2` 解析出**当刻最新版**框架模块目录（版本不固化）。
2. 读取该模块下的 `testdata/etc/etc.toml` 作为**唯一模板**。
3. 按角色裁剪 section，**逐行保留配置项注释**。
4. 把 `pid` 与角色自身的 `name` 替换为该服务的值。

模板位置：`<框架模块>/testdata/etc/etc.toml`。

## 2. 裁剪规则

各角色保留的 section（前缀匹配，选中 `cluster.node` 会一并带上 `cluster.node.linker`）：

| 角色 | 保留 section |
| --- | --- |
| gate | `cluster.gate`、`packet`、`log`、`registry.nacos`、`network.ws.server`、`locate.redis` |
| hall | `cluster.node`、`task`、`pprof`、`transport.grpc.client`、`packet`、`log`、`registry.nacos`、`config.nacos`、`locate.redis`、`lock.redis`、`eventbus.redis` |
| mesh | `cluster.mesh`、`task`、`pprof`、`transport.grpc`、`packet`、`log`、`registry.nacos`、`config.nacos`、`locate.redis`、`cache.redis`、`lock.redis`、`eventbus.redis` |
| web | `http`、`log`、`registry.nacos`、`transport.grpc.client` |

裁剪原则：**只保留本进程实际读取的 section**——代码里 `Set` 了哪类设施/组件，就必须有对应 section（例如设了缓存就要有 `[cache.redis]`）。

生成时丢弃（脚本内 `drop` 列表，均有明确理由）：

| 丢弃项 | 原因 |
| --- | --- |
| `cluster.*.metadata` | 模板里的 `key = "value"` 示例会把假元数据注入注册中心 |
| `log.terminals` | **模板同时用数组与表声明**（`terminals = [...]` 与 `[log.terminals]`），严格 TOML 会报 `Cannot declare ... twice` |
| `log.aliyun`、`log.tencent` | 仅当 `terminals` 含云端日志时才需要 |
| `network.ws.server.proxy` | 本版代码读取的是 `proxyMode` / `proxyOptions`，模板中的该块**无效** |

## 3. 生成后仍需人工确认的值

生成结果取自**模板默认值**，以下项目相关值需按实际修改：

- `registry.nacos.namespaceId`（模板为空）
- 各处地址（`addrs` / `urls` / `addr`）与端口
- `packet.routeBytes` / `seqBytes` / `bufferBytes` 等协议参数（模板为框架默认值）
- 各凭据（`username` / `password` / `accessKey` 等）

部署用配置不在这里：它放在 `internal/share/etc/etc.<project>.<env>.toml`，构建期由 `build.sh` 分发。详见 [构建与交付](构建与交付.md)。

## 4. 易错点

- **命名空间前缀来自配置文件名**：框架读取的 key 形如 `etc.cluster.node.id`，其 `etc.` 前缀对应文件名 `etc.toml`；**改文件名会导致全部配置失效**。
- **模板可能滞后于代码**：本版 `network.ws.server.proxy` 已不被读取（改读 `proxyMode`/`proxyOptions`）。升级框架后重新生成并复核 `drop` 列表。
- **模板尚未覆盖的 key**（代码读取、模板未给，走框架默认）：`log.file.flushInterval`、`cluster.mesh.weight`、`registry.nacos.heartbeat`、`network.ws.server` 的 `readBufferSize`/`writeBufferSize`/`closeTimeout`/`proxyMode`/`proxyOptions`。需要时按源码自行补。
- **别整份拷贝模板**：不裁剪会遗留 etcd/consul/memcache/kafka/rpcx 等本项目不用的模块，增加误配风险。
