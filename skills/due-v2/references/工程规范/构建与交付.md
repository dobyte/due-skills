# 构建与交付

## 1. 交付模型

**宿主机（或 CI）编译 → Dockerfile 只做运行时打包 → 推镜像 → 部署。**

- 镜像内**没有 Go 工具链**，因此不存在"镜像里的 Go 版本"与 `go.mod` 版本漂移的问题——天然契合"依赖版本不固化、按当刻最新解析"。
- 二进制与配置在构建期物化，运行期零编译。

## 2. 相关文件

| 路径 | 作用 | 是否入库 |
| --- | --- | --- |
| `build.sh` | 单服务构建发布：编译 + 打包 + 推送 | 是 |
| `<service>/Dockerfile` | 运行时镜像定义 | 是 |
| `internal/share/etc/etc.<project>.<env>.toml` | 共享配置源（按 项目 × 环境） | 是 |
| `<service>/etc/etc.toml` | 本地开发配置 | 是 |
| `<service>/etc/etc.<env>.toml` | 构建期生成 | 否 |
| `<service>/main` | 编译产物 | 否 |

## 3. 构建流程

1. **复制共享配置**：`internal/share/etc/etc.<project>.<env>.toml` → `<service>/etc/etc.<env>.toml`
2. **进入服务目录编译**：`CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o main .`
3. **打包**：`docker build --build-arg ENV=<env> <service>/`（**上下文 = 服务目录**）
4. **推送**镜像，清理中间产物（`main`、生成的 `etc.<env>.toml`）
5. 按环境更新部署（如 test 环境更新 k8s）

CI 应**固定宿主机工具链版本**（编译发生在镜像之外，镜像不受影响）。

## 4. Dockerfile 约定

```dockerfile
FROM <基础镜像>

# 构建期传入环境：test / audit / master
ARG ENV

COPY main /home/server/main
COPY ./etc/etc.${ENV}.toml /home/server/etc/etc.toml

WORKDIR /home/server/

EXPOSE <端口>

ENTRYPOINT ["/home/server/main"]
```

- `ARG ENV` 决定打入哪份环境配置。
- 端口约定：**Gate** = 客户端端口 + 内部 RPC 端口；**Node / Mesh** = 内部 RPC 端口；**HTTP 服务** = HTTP 端口。

## 5. 基础镜像要求

基础镜像**必须自带**：

- **CA 根证书**——否则 HTTPS 出站（注册中心、短信、微信、支付等）报 `x509: certificate signed by unknown authority`。
- **时区数据**——否则 `timezone = "Local"` 失效、时间退化为 UTC。

若基础镜像不含，需自行补（alpine 系）：`apk add --no-cache ca-certificates tzdata`。

## 6. 多环境

- 维度：`project × environment`（如 test / audit / master）。
- **配置选择发生在构建期**（`ARG ENV`），不是运行期。
- 环境差异**全部收敛**在 `internal/share/etc/`；服务目录里的 `etc.toml` 只服务本地开发。

## 7. 反模式

- **在镜像内编译**（`FROM golang:...` 多阶段构建）：把 Go 版本固化进 Dockerfile，与 `go.mod` 的动态版本必然漂移；镜像还被迫携带整套工具链。
- 运行时基础镜像**缺 CA 证书 / 时区数据**。
- 构建上下文用**仓库根**，`COPY . .` 把无关目录、`.git`、本地密钥一起带进镜像层。
- 把构建期生成的 `etc/etc.<env>.toml`、`main` **提交入库**。
- 环境差异散落在各服务的 `etc.toml`，而非收敛到共享配置目录。
