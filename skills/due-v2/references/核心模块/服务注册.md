# 服务注册 (Registry)

## 概述

服务注册模块是 Due 框架的核心组件，提供服务发现、服务注册、负载均衡等分布式系统基础能力。支持 Consul、Etcd、Nacos、Polaris 等主流注册中心，用于集群实例的服务注册和发现，支撑无感知停服、重启、动态扩容等能力。

> **v2.6.8 变更**：Consul/Nacos/Polaris 的路由元数据从 JSON/文本格式压缩为紧凑的 flag range 编码，避免超过 Consul Meta 512B 限制；无效实例跳过而非整体失败；Polaris 新增 `cacheDir`/`logDir` 配置项；统一路由错误导出到 `errors` 包。详见文末「版本更新摘要」。

## 包路径

```go
import "github.com/dobyte/due/registry/consul/v2"
```

## Consul 注册中心

### 配置参数

```toml
[registry.consul]
    # 客户端连接地址，默认为 127.0.0.1:8500
    addr = "127.0.0.1:8500"
    # 是否启用健康检查，默认为 true
    healthCheck = true
    # 健康检查时间间隔（秒），仅在启用健康检查后生效，默认为 10
    healthCheckInterval = 10
    # 健康检查超时时间（秒），仅在启用健康检查后生效，默认为 5
    healthCheckTimeout = 5
    # 是否启用心跳检查，默认为 true
    heartbeatCheck = true
    # 心跳检查时间间隔（秒），仅在启用心跳检查后生效，默认为 10
    heartbeatCheckInterval = 10
    # 健康检测失败后自动注销服务时间（秒），默认为 30
    deregisterCriticalServiceAfter = 30
```

> **v2.6.8 路由元数据压缩**：路由 ID 与选项不再以 `"id-opts"` 逐行编码，而是压缩为 flag range 格式并按 512 字节分块存储，兼容旧版 `"id-opts"` 格式的滚动升级场景。

### 使用示例

```go
package main

import (
    "github.com/dobyte/due/registry/consul/v2"
    "github.com/dobyte/due/v2"
    "github.com/dobyte/due/v2/cluster/node"
)

func main() {
    // 创建容器
    container := due.NewContainer()
    // 创建服务注册
    registry := consul.NewRegistry()
    // 创建节点组件
    component := node.NewNode(
        node.WithRegistry(registry),
    )
    // 添加节点组件
    container.Add(component)
    // 启动容器
    container.Serve()
}
```

## Nacos 注册中心

### 配置参数

```toml
[registry.nacos]
    # 服务器地址 [scheme://]ip:port[/nacos]。默认为 ["http://127.0.0.1:8848/nacos"]
    urls = ["http://127.0.0.1:8848/nacos"]
    
    # 集群名称。默认为 DEFAULT
    clusterName = "DEFAULT"
    
    # 群组名称。默认为 DEFAULT_GROUP
    groupName = "DEFAULT_GROUP"
    
    # 请求 Nacos 服务端超时时间，默认为 3s
    timeout = "3s"
    
    # ACM 的命名空间 Id。默认为空
    namespaceId = ""
    
    # Nacos 服务端的 API 鉴权 Username / Password
    username = ""
    password = ""
    
    # 日志存储路径，默认 ./run/nacos/naming/log
    logDir = "./run/nacos/naming/log"
    
    # 日志输出级别：debug、info、warn、error。默认为 info
    logLevel = "info"
```

> **v2.6.8 路由编码**：路由信息编码为紧凑的 flag range（而非 JSON），与 Consul/Polaris 保持一致。路由快照与路由限制对齐，避免解码超限。无效路由元数据解码失败时仅记录警告，不会导致整个查询失败。

## Polaris 注册中心

### 配置参数

```toml
[registry.polaris]
    # 读写模式。可选：read-only | write-only | read-write，默认为 read-only
    mode = "read-only"
    # 服务器地址，默认为 ["127.0.0.1:8091"]
    urls = ["127.0.0.1:8091"]
    # 命名空间，默认为 default
    namespace = "default"
    # 配置分组，默认为 default
    group = "default"
    # 请求 Polaris 服务端超时时间，默认为 3s
    timeout = "3s"
    # 与 Polaris 服务端通信协议，默认为 grpc
    protocol = "grpc"
    # 缓存目录（v2.6.8 新增），默认 ./run/polaris/naming/cache
    cacheDir = "./run/polaris/naming/cache"
    # SDK 日志目录（v2.6.8 新增），默认 ./run/polaris/naming/log
    logDir = "./run/polaris/naming/log"
```

> **v2.6.8 路由编码**：与 Nacos 对齐，路由编码为紧凑的 flag range 格式而非 JSON，同时兼容旧版 JSON 格式以支持滚动升级。无效 metadata 的实例会被跳过并记录警告，不会导致整个快照失败。polaris-go 升级到 v1.7.2。

## 核心 API

### 注册中心接口

```go
type Registry interface {
    // 返回注册发现组件名称
    Name() string
    // 注册服务实例
    Register(ctx context.Context, ins *ServiceInstance) error
    // 注销服务实例
    Deregister(ctx context.Context, ins *ServiceInstance) error
    // 监听同名服务实例变化
    Watch(ctx context.Context, serviceName string) (Watcher, error)
    // 获取服务实例列表
    Services(ctx context.Context, serviceName string) ([]*ServiceInstance, error)
    // 关闭注册发现组件
    Close() error
}
```

### 服务实例结构

```go
type ServiceInstance struct {
    ID       string            // 服务实例ID
    Name     string            // 服务名称
    Kind     string            // 服务实体类型
    Alias    string            // 服务实体别名
    State    string            // 服务实例状态
    Events   []int             // 服务事件集合
    Routes   []Route           // 服务路由ID
    Services []string          // 服务路由列表
    Endpoint string            // 微服务实体暴露端口
    Weight   int               // 服务路由加权轮询权重
    Metadata map[string]string // 元数据
}

type Route struct {
    ID         int32 // 路由ID
    Internal   bool  // 是否为内部路由
    Stateful   bool  // 是否为有状态路由
    Authorized bool  // 是否需要鉴权
}
```

### Watcher 接口

```go
type Watcher interface {
    // 获取下一个服务实例列表
    Next() ([]*ServiceInstance, error)
    // 停止监听
    Stop() error
}
```

### 统一错误（v2.6.8）

```go
import "github.com/dobyte/due/v2/errors"

errors.ErrInvalidRoutes          // 路由元数据解码失败
errors.ErrTooManyRoutes          // 路由数量超过上限（65536）
errors.ErrAllInstancesParseFailed // Polaris 所有健康实例 metadata 均解析失败
```

## 服务注册示例

```go
package main

import (
    "context"

    "github.com/dobyte/due/registry/consul/v2"
    "github.com/dobyte/due/v2/registry"
)

func main() {
    // 创建注册中心
    reg := consul.NewRegistry()

    // 注册服务
    err := reg.Register(context.Background(), &registry.ServiceInstance{
        ID:       "service-1",
        Name:     "my-service",
        Kind:     "node",
        Endpoint: "127.0.0.1:8080",
        Weight:   1,
        Metadata: map[string]string{
            "version": "v1.0.0",
        },
    })
    if err != nil {
        panic(err)
    }

    // 获取服务列表
    services, err := reg.Services(context.Background(), "my-service")
    if err != nil {
        panic(err)
    }
    for _, ins := range services {
        println("service instance:", ins.ID)
    }

    // 监听服务变化
    watcher, err := reg.Watch(context.Background(), "my-service")
    if err != nil {
        panic(err)
    }
    defer watcher.Stop()

    for {
        instances, err := watcher.Next()
        if err != nil {
            break
        }
        // 处理服务变更
        handleServiceChange(instances)
    }
}
```

## 最佳实践

1. **服务命名**:
   - 使用清晰的服务名称便于识别
   - 服务ID应全局唯一

2. **健康检查**:
   - 启用健康检查确保服务可用性
   - 合理设置检查间隔和超时时间

3. **元数据管理**:
   - 控制元数据数量（建议不超过 20 个）
   - 键长度不超过 127 字符，值长度不超过 512 字符

4. **高可用**:
   - 配置自动注销时间防止僵尸服务
   - 使用心跳机制保持服务活性

5. **路由兼容性**:
   - v2.6.8 的紧凑格式与旧版 JSON/text 格式：**新版可解码旧格式，旧版不能解码新格式**，滚动升级时先升级读取方或整批升级
   - 路由元数据解码失败只记录警告，不中断整个服务发现

## 版本更新摘要

### v2.6.8

**Breaking Changes**:
- 无 API 签名变更；路由元数据编码从 `"id-opts"` / JSON 改为紧凑 flag range，已提供向后兼容解码
- 新版可读旧格式，**旧版不能读新格式**，滚动升级时先升级读取方或整体升级

**新特性**:
- Consul/Nacos/Polaris 路由元数据压缩为紧凑 flag range 编码，避免 Consul Meta 512B 限制
- Consul 按 512 字节分块；Nacos 路由快照与路由上限对齐，路由解码有上限保护
- Polaris 跳过无效 metadata 的实例（仅警告），不再整体失败；全实例解析失败时返回 `ErrAllInstancesParseFailed`
- Nacos 全实例解析失败时保留上一份实例快照，避免清空路由表
- Consul/Etcd 增加 closed 状态、watch 重试与幂等 Stop，关闭时停止 registrar / watcher
- Polaris registry 新增 `cacheDir`/`logDir` 配置项，SDK logger 只初始化一次
- 统一路由错误导出：`errors.ErrInvalidRoutes`、`errors.ErrTooManyRoutes`、`errors.ErrAllInstancesParseFailed`
- polaris-go 升级到 v1.7.2；sonic 升级到 v1.15.5（所有模块）

**修复**:
- 无效实例逐个跳过并记录日志，不再丢弃整个发现更新
- Nacos 注册中心接受不带 scheme 的服务地址（默认按 http 解析）
- Polaris 配置目录为空时回退默认目录；应用自定义 logger 不再被重置

### v2.6.7

- `registry/nacos` 客户端 SDK 升级到 v2.3.6（与配置中心的 Nacos 3.x 管理端支持配套）
- 注册中心公开 API 与元数据格式无变化

### v2.6.6 / v2.6.5 / v2.6.4 / v2.6.3

- 仅子模块依赖对齐；服务注册 API 与行为无变化
