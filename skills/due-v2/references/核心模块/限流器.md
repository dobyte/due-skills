# 限流器 (Limiter)

## 概述

Due v2.6.7 引入统一限流体系，分为**框架级 limiter 子模块**和 **Gate 内置 per-connection GCRA** 两层，二者解耦：

1. **框架级 limiter 子模块**（`github.com/dobyte/due/v2/limiter`）：面向业务逻辑的令牌桶限流，提供 `Maker`/`Limiter` 抽象 + `limiter/memory`（进程内）+ 独立子模块 `limiter/redis`（分布式）
2. **Gate 内置 per-connection GCRA 限流器**：面向连接级防护，**Gate 自己实现了 `connLimiter`**（见 `cluster/gate/limiter.go`），不依赖 limiter 包的 Maker/Limiter 抽象。配置前缀 `etc.cluster.gate.limiter.*`

> **v2.6.7 新增**。limiter 是 due/v2 的顶层子包（非独立 go.mod 子模块）。

## 框架级 Limiter（业务限流）

### 包路径

```go
import "github.com/dobyte/due/v2/limiter"         // 抽象 Maker/Limiter/Rule/Result
import "github.com/dobyte/due/v2/limiter/memory"  // 进程内 token bucket backend

// 独立子模块（单独 go.mod）
import "github.com/dobyte/due/limiter/redis/v2"
```

### 核心抽象

以下签名**直接来自** `limiter/limiter.go` v2.6.8，按源文字面量整理：

```go
package limiter

// FailurePolicy 后端不可用时的行为
type FailurePolicy int
const (
    FailOpen   FailurePolicy = iota + 1 // 后端不可用时放行
    FailClosed                           // 后端不可用时拒绝
)

// Rule 限流规则（Token Bucket 语义）
type Rule struct {
    Quota  float64       // 周期内 token 总数
    Period time.Duration // 窗口周期；默认 1s
    Burst  int           // bucket 容量上限；默认 ceil(Quota)
}

// Maker 负责为命名 scene 产出 Limiter
type Maker interface {
    // Make 为指定 scene 创建 Limiter；scene 名在 Maker 作用域内必须唯一
    Make(name string, rule Rule) (Limiter, error)
    Close() error
}

// Limiter 令牌桶实例
type Limiter interface {
    // Allow 为指定 key 取 n 个 token（n 默认 1）；拒绝不是 error，通过 Result.Allowed 报告
    Allow(ctx context.Context, key string, n ...int) (Result, error)
}

// Result 决策结果
type Result struct {
    Allowed    bool          // 是否允许
    Limit      int           // bucket 容量
    Remaining  int           // 决策后剩余 token 数
    RetryAfter time.Duration // 拒绝时建议客户端等待时间
    ResetAfter time.Duration // bucket 完全 refill 所需时间
    Degraded   bool          // 是否由 fail-open 放行（后端不可用场景）
}
```

### 全局函数

```go
func SetMaker(maker Maker)                // 设置全局 Maker（关闭旧的）
func GetMaker() Maker                     // 获取全局 Maker
func Make(name string, rule Rule) (Limiter, error) // 通过全局 Maker 创建 Limiter
func Close() error                        // 关闭全局 Maker
```

### Rule.Normalize 与 FailOpen/FailClosed

- `Rule.Normalize()` 校验并填默认：`Period<=0 → 1s`，`Burst<=0 → ceil(Quota)`
- Maker 实例化时通过 Option 指定后端不可用时的策略（memory 无此选项，redis 有熔断 + FailPolicy）

### memory 后端（进程内）

```go
import (
    "github.com/dobyte/due/v2/limiter"
    "github.com/dobyte/due/v2/limiter/memory"
)

func main() {
    // 全局 Maker，默认 memory 后端
    // memory.NewMaker 接受两个 Option：WithPrefix / WithCleanupInterval
    limiter.SetMaker(memory.NewMaker(
        memory.WithPrefix("myapp"),            // key 前缀
        memory.WithCleanupInterval(time.Minute), // 过期 bucket 清理周期
    ))

    // 创建 Limiter：scene 名 + Rule
    // 同一 scene + 同一 normalized Rule 复用共享 bucket 状态
    // 同一 scene + 不同 normalized Rule → errors.ErrConflictLimiterRule
    l, err := limiter.Make("scene-login", limiter.Rule{
        Quota:  100,     // float64
        Period: time.Second,
        Burst:  200,
    })
    if err != nil { panic(err) }

    // Allow 时 key 才是维度（uid/ip 等）
    res, err := l.Allow(context.Background(), "uid-123")
    if err != nil { panic(err) }

    if !res.Allowed {
        // res.RetryAfter 告诉客户端多久再试
        // res.Limit / res.Remaining / res.ResetAfter 可用于业务侧响应
    }

    if res.Degraded {
        // 后端不可用时 fail-open 放行 — 记日志告警
    }
}
```

### memory 后端实现要点

- **32 分片 sync.Map**（FNV-1a 哈希，shard count 是 2 的幂）
- **cursor-based 驱逐**：每 pass 每 shard 最多扫 512 bucket，100k key 清理 ~1.55ms
- **零分配热路径**：`Allow` ~52ns/op、**0 alloc**
- **scene 唯一性**：同 scene 不同 Rule → `errors.ErrConflictLimiterRule`（防止共享 bucket 状态错位）
- **prefix + scene 拼接**在 `Make` 时一次完成，不在每次 Allow 调用

### redis 后端（分布式）

```go
import redislimiter "github.com/dobyte/due/limiter/redis/v2"
import "github.com/dobyte/due/v2/limiter"

func main() {
    limiter.SetMaker(redislimiter.NewMaker(
        redislimiter.WithAddrs([]string{"127.0.0.1:6379"}),
        redislimiter.WithPolicy(limiter.FailOpen), // 后端故障时放行
    ))
    // 用法同 memory
}
```

### redis 后端 etc 配置（独立子模块）

```toml
[limiter.redis]
    # Redis 地址列表
    addrs = ["127.0.0.1:6379"]
    # 超时时间，默认 3s
    timeout = "3s"
    # 内置客户端 retries，默认 1（-1 禁用）
    retries = 1
    # 熔断阈值：连续失败次数到后直接按 FailPolicy 返回
    circuitThreshold = 5
    # 熔断恢复时间
    circuitRecover = "5s"
```

### redis 后端实现要点

- **原子 Lua 脚本**：fixed-point token bucket state（string + SET PX），避免 Lua 浮点格式开销
- **熔断（circuit breaker）**：连续失败打开 → 直接按 FailPolicy 返回，不再等待超时
- **FailOpen / FailClosed**：后端故障时返回 `Result.Degraded=true`（FailOpen）或 `Result.Allowed=false`（FailClosed）
- **旧数据迁移**：首次访问时自动把 legacy hash key 迁移到 fixed-point string

### 统一错误

```go
import "github.com/dobyte/due/v2/errors"

errors.ErrLimiterUnavailable     // 后端不可用
errors.ErrConflictLimiterRule    // 同一 scene 注册了不同 Rule（memory 实现里）
errors.ErrInvalidLimiterRule     // Rule 字段非法（Quota<=0 / NaN / Inf）
errors.ErrMissingLimiterInstance // 未设置全局 Maker 时调用 limiter.Make
errors.ErrIllegalOperation       // 关闭后再操作
```

### 最佳实践

1. **scene 维度**：按业务命名（`"scene-login"`、`"scene-send-sms"`），dimension key 在 `Allow(ctx, key)` 时传入
2. **burst 大于 quota**：允许突发（登录风暴等），避免一次性限流
3. **主动 Close**：全局 Maker 会被 `SetMaker` 自动关闭旧的；进程退出时记得 `limiter.Close()`
4. **FailOpen 合适场景**：认证/登录/支付等不应因 Redis 故障完全拒绝，可用 FailOpen + 日志告警

## Gate 内置 per-connection GCRA 限流器

### 概述

Gate 自 v2.6.7 起内置 per-connection GCRA 限流，**独立于 limiter 子模块**（Gate 自己实现了 `connLimiter`）。配置通过 etc 读取，Go Option 也可覆盖。

### 架构

```
Gate read loop (per-connection)
  ↓
connLimiter.Check(now, frame)
  ├─ allowed  → 下发 handler，更新 GCRA bucket
  └─ over-limit
       ├─ drop 业务帧 + warn
       └─ violation counter++
            └─ 超过 closeThreshold → defer Close（异步，不在 read loop 里同步 close）
```

- **GCRA**：虚拟调度时间 VIT = max(TAT, now) + 1/Q；若 now + τ < VIT 则通过；GCRA 天然整数化
- **shard sync.Map + free list**：256 shard（2 的幂，按 connectionID 哈希）；per-shard capped free list（默认 1024）复用 bucket
- **cache line padding**：shard 结构体 padding 64B 避免 false sharing
- **lazily 创建**：连接首次到业务帧（握手/心跳帧绕过）时才创建 bucket
- **close defer**：限流触发的 Close 放到 read loop defer 外执行，避免死锁

### etc 配置项

真实配置 key（直接取自 `cluster/gate/options.go` 常量定义）：

```toml
[cluster.gate.limiter]
    # 窗口周期，默认 1s（从 etc.cluster.gate.limiter.period 读取）
    period = "1s"
    # 周期内允许的业务帧数；0 表示关闭限流（默认 0，即关闭）
    quota = 0
    # 突发容量（GCRA τ），默认 ceil(quota)
    burst = 0
    # 连续违规达到多少次后强制关闭连接，默认 100
    closeThreshold = 100
```

> ⚠️ **这是 cluster 层面配置**，**不属于** `network.tcp.server.*`、`network.ws.server.*` 等传输层配置。所有传输协议（TCP/WS/KCP/QUIC）的 Gate limiter 配置统一。

### Go Option 覆盖

```go
import "github.com/dobyte/due/v2/cluster/gate"

g := gate.NewGate(
    gate.WithLimiterQuota(1000),           // float64
    gate.WithLimiterPeriod(time.Second),   // time.Duration
    gate.WithLimiterBurst(2000),           // int
    gate.WithLimiterCloseThreshold(10),    // int
)
```

Go Option 优先级高于 etc 配置；`WithLimiterQuota(0)` 强制关闭。

### 行为说明

| 帧类型 | 是否走 limiter |
|--------|---------------|
| 握手帧（Handshake） | 绕过 |
| 心跳帧（Heartbeat） | 绕过 |
| 业务帧（Business/Push） | **走 limiter**，超额 drop |

### 与 limiter 子模块的分工

| 场景 | 用哪个 |
|------|-------|
| 连接级防护（每个 TCP/WS 连接配额） | Gate 内置 connLimiter（etc.cluster.gate.limiter.*） |
| 业务级防护（登录、短信、接口配额） | limiter 子模块（memory/redis backend） |
| 分布式跨 Gate 统一配额 | limiter + redis |
| 单机多 Scene | limiter + memory（每个 scene 一个 Maker） |

## 版本更新摘要

### v2.6.7

**Breaking Changes**：
- 无 API 签名变更（limiter 包是全新引入）
- 同一 scene 注册不同 Rule 现在返回 `errors.ErrConflictLimiterRule`（**不会 silent 覆盖**）

**新特性**：
- 新增 `limiter`、`limiter/memory`、独立子模块 `limiter/redis` 令牌桶限流体系
- Gate 内置 per-connection GCRA 限流器（256 shard + free list + cache line padding）
- redis limiter 熔断、fixed-point 状态、FailOpen/FailClosed
- memory limiter cursor-based 驱逐（0.57ms / 100k key）、0 alloc hot path
- 统一导出错误：`errors.ErrLimiterUnavailable`、`errors.ErrConflictLimiterRule`、`errors.ErrInvalidLimiterRule`、`errors.ErrMissingLimiterInstance`
