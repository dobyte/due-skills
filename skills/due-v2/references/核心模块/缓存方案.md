# 缓存方案 (Cache)

## 概述

缓存方案是 Due 框架的扩展组件，提供高性能的缓存管理能力。支持 Redis、Memcache 等存储后端，用于加速数据访问和减轻数据库压力。

## 包路径

```go
import "github.com/dobyte/due/cache/redis/v2"
```

## Redis 缓存

### 配置参数

```toml
[cache.redis]
    # 客户端连接地址
    addrs = ["127.0.0.1:6379"]
    # 数据库号
    db = 0
    # 用户名
    username = ""
    # 密码
    password = ""
    # 私钥文件
    keyFile = ""
    # 证书文件
    certFile = ""
    # CA证书文件
    caFile = ""
    # 最大重试次数
    maxRetries = 3
    # key前缀，默认为cache
    prefix = "due:cache"
    # 空值，默认为cache@nil
    nilValue = "cache@nil"
    # 空值过期时间，默认为10s
    nilExpiration = "10s"
    # 最小过期时间，默认为1h
    minExpiration = "1h"
    # 最大过期时间，默认为24h
    maxExpiration = "24h"
```

### 使用示例

```go
package main

import (
    "github.com/dobyte/due/cache/redis/v2"
    "github.com/dobyte/due/v2/cache"
)

func main() {
    // 创建 Redis 缓存并设置为全局缓存实例
    cache.SetCache(redis.NewCache())
}
```

## 核心 API

### 缓存接口

```go
type Cache interface {
    // 判断指定键是否存在
    Has(ctx context.Context, key string) (bool, error)
    // 获取缓存值，返回 Result 结果对象；键不存在时返回可选默认值 def
    Get(ctx context.Context, key string, def ...any) Result
    // 设置缓存值。expiration 可选：省略时使用配置的随机过期时间，
    // 大于 0 表示显式过期时间，等于 -1 表示保持原有过期时间，小于 -1 表示永不过期
    Set(ctx context.Context, key string, value any, expiration ...time.Duration) error
    // 获取缓存值，键不存在时通过 fn 生成并写入缓存
    GetSet(ctx context.Context, key string, fn SetValueFunc) Result
    // 删除指定键，返回实际删除的键数量
    Delete(ctx context.Context, keys ...string) (int64, error)
    // 自增整型
    IncrInt(ctx context.Context, key string, value int64) (int64, error)
    // 自增浮点型
    IncrFloat(ctx context.Context, key string, value float64) (float64, error)
    // 自减整型
    DecrInt(ctx context.Context, key string, value int64) (int64, error)
    // 自减浮点型
    DecrFloat(ctx context.Context, key string, value float64) (float64, error)
    // 为键添加前缀
    AddPrefix(key string) string
    // 返回底层缓存客户端
    Client() any
    // 关闭缓存
    Close() error
}
```

### 缓存结果对象

`Get`、`GetSet` 返回的 `Result` 接口提供了将缓存值转换为各种类型的方法（如 `Int64`、`String`、`Bool`、`Slice`、`Map` 等），也可通过 `Scan(pointer any)` 将结果扫描到目标对象中，或通过 `Err()` 获取错误。

### 全局函数

除接口方法外，`cache` 包还提供了操作全局缓存实例的便捷函数：`SetCache`、`GetCache`、`Has`、`Get`、`Set`、`GetSet`、`Delete`、`IncrInt`、`IncrFloat`、`DecrInt`、`DecrFloat`、`AddPrefix`、`Client`、`Close`。未设置全局缓存实例时，这些函数会返回 `errors.ErrMissingCacheInstance`。

## 使用场景示例

### 基础使用

```go
package main

import (
    "context"
    "time"
    "github.com/dobyte/due/cache/redis/v2"
)

func main() {
    // 创建缓存
    cache := redis.NewCache()
    
    ctx := context.Background()
    
    // 设置缓存
    err := cache.Set(ctx, "user:1001", map[string]interface{}{
        "id":   1001,
        "name": "Alice",
    }, 10*time.Minute)
    if err != nil {
        panic(err)
    }
    
    // 获取缓存，Scan 将结果扫描到目标对象
    var user map[string]interface{}
    if err = cache.Get(ctx, "user:1001").Scan(&user); err != nil {
        panic(err)
    }
    
    println(user["name"].(string))
    
    // 删除缓存，返回实际删除的键数量
    n, err := cache.Delete(ctx, "user:1001")
    if err != nil {
        panic(err)
    }
    _ = n
}
```

### 缓存穿透防护

```go
package main

import (
    "context"
    "time"
    "github.com/dobyte/due/cache/redis/v2"
)

func getUser(ctx context.Context, cache *redis.Cache, userID int64) (*User, error) {
    key := fmt.Sprintf("user:%d", userID)
    
    // 尝试从缓存获取
    var user User
    if err := cache.Get(ctx, key).Scan(&user); err == nil {
        return &user, nil
    }
    
    // 缓存未命中，查询数据库
    u, err := queryUserFromDB(ctx, userID)
    if err != nil {
        return nil, err
    }
    
    // 写入缓存
    if err = cache.Set(ctx, key, u, 10*time.Minute); err != nil {
        // 记录日志但不影响业务
        log.Warnf("Failed to set cache: %v", err)
    }
    
    return u, nil
}
```

### 批量操作

```go
package main

import (
    "context"
    "github.com/dobyte/due/cache/redis/v2"
)

func batchDeleteCache(ctx context.Context, cache *redis.Cache, keys []string) (int64, error) {
    // 批量删除缓存，返回实际删除的键数量
    return cache.Delete(ctx, keys...)
}
```

## 最佳实践

1. **缓存策略**:
   - 使用合理的过期时间避免数据不一致
   - 对于热点数据设置较长的缓存时间

2. **缓存穿透**:
   - 对于空值也进行缓存（设置较短过期时间）
   - 使用布隆过滤器预防缓存穿透

3. **缓存雪崩**:
   - 为缓存添加随机过期时间
   - 使用多级缓存架构

4. **Key命名**:
   - 使用清晰的key前缀避免冲突
   - 包含业务标识便于管理和调试

5. **序列化**:
   - 缓存写入时会通过 `xconv.String` 将值转换为字符串，读取时可通过 `Result` 的各类方法或 `Scan` 还原
   - 复杂结构建议在业务层自行进行序列化，读取后按需转换
