# 分布式锁 (Lock)

## 概述

分布式锁模块是 Due 框架的扩展组件,提供分布式环境下的互斥访问能力。支持 Redis、Memcache 等存储后端,确保多节点环境下的数据一致性。

## 包路径

```go
import "github.com/dobyte/due/lock/redis/v2"
```

## Redis 分布式锁

### 配置参数

```toml
[lock.redis]
    # 客户端连接地址
    addrs = ["127.0.0.1:6379"]
    # 数据库号
    db = 0
    # 用户名
    username = ""
    # 密码
    password = ""
    # 私钥文件
    keyFile = ""
    # 证书文件
    certFile = ""
    # CA证书文件
    caFile = ""
    # 最大重试次数
    maxRetries = 3
    # key前缀
    prefix = "due:lock"
    # 锁过期时间（自动续约），默认为3s
    expiration = "3s"
    # 循环获取锁的频率间隔时间，默认为20ms
    acquireInterval = "20ms"
    # 循环获取锁的最大重试次数，默认为0，<=0则为无限次
    acquireMaxRetries = 0
```

### 使用示例

```go
package main

import (
    "github.com/dobyte/due/lock/redis/v2"
    "github.com/dobyte/due/v2/lock"
)

func main() {
    // 创建锁制造器并设置为全局锁制造器
    lock.SetMaker(redis.NewMaker())
}
```

## 核心 API

### 锁制造器接口

```go
type Maker interface {
    // 创建指定名称的锁
    Make(name string) Locker
    // 关闭制造器
    Close() error
}
```

### 锁实例接口

```go
type Locker interface {
    // 获取锁（阻塞式，直到成功）
    Acquire(ctx context.Context) error
    // 尝试获取锁，expiration 为可选的固定过期时间
    TryAcquire(ctx context.Context, expiration ...time.Duration) error
    // 释放锁
    Release(ctx context.Context) error
}
```

### 全局函数

`lock` 包提供了操作全局锁制造器的便捷函数：`SetMaker`、`GetMaker`、`Make`、`Close`。未设置全局制造器时，`Make` 返回 `nil`、`Close` 不做任何处理。

## 使用场景示例

### 基础使用

```go
package main

import (
    "context"

    "github.com/dobyte/due/lock/redis/v2"
    "github.com/dobyte/due/v2/lock"
)

func main() {
    // 设置全局锁制造器
    lock.SetMaker(redis.NewMaker())
    
    // 创建名为 my-resource 的锁实例
    locker := lock.Make("my-resource")
    
    ctx := context.Background()
    
    // 获取锁（阻塞式，直到成功）
    if err := locker.Acquire(ctx); err != nil {
        panic(err)
    }
    defer locker.Release(ctx)
    
    // 执行业务逻辑
    doSomething()
}
```

### 尝试获取锁

```go
package main

import (
    "context"

    "github.com/dobyte/due/lock/redis/v2"
    "github.com/dobyte/due/v2/lock"
)

func main() {
    // 设置全局锁制造器
    lock.SetMaker(redis.NewMaker())
    
    // 创建名为 my-resource 的锁实例
    locker := lock.Make("my-resource")
    
    ctx := context.Background()
    
    // 尝试获取锁（不阻塞，失败立即返回错误）
    if err := locker.TryAcquire(ctx); err != nil {
        println("Failed to acquire lock")
        return
    }
    defer locker.Release(ctx)
    
    // 执行业务逻辑
    doSomething()
}
```

### 锁续期

`Acquire` 获取锁成功后会自动开启后台续期，续期周期为锁过期时间的一半，直至显式释放或锁丢失，无需手动续期。`TryAcquire` 在不指定过期时间时同样会自动续期；若指定了固定的过期时间，则锁到期后不再续期。

```go
package main

import (
    "context"

    "github.com/dobyte/due/lock/redis/v2"
    "github.com/dobyte/due/v2/lock"
)

func main() {
    // 设置全局锁制造器
    lock.SetMaker(redis.NewMaker())
    
    // 创建名为 my-resource 的锁实例
    locker := lock.Make("my-resource")
    
    ctx := context.Background()
    
    // 获取锁，成功后自动开启后台续期
    if err := locker.Acquire(ctx); err != nil {
        panic(err)
    }
    defer locker.Release(ctx)
    
    // 长时间任务，锁会自动续期
    doLongRunningTask()
}
```

## 最佳实践

1. **超时设置**:
   - 设置合理的锁过期时间（`expiration`，默认3s）防止死锁
   - 过期时间应大于业务执行时间

2. **锁续期**:
   - `Acquire` 会自动进行后台续期，无需手动续期
   - 过期时间过短会导致续期难以在锁失效前完成，需持续持锁时建议不低于 1s
   - 避免锁过期导致并发问题

3. **错误处理**:
   - 处理获取锁失败的情况
   - 通过 `acquireMaxRetries` 与 `acquireInterval` 控制重试行为

4. **资源释放**:
   - 使用 `defer` 确保锁被释放
   - 处理释放锁时的错误

5. **Key命名**:
   - 使用清晰的key前缀避免冲突
   - 包含业务标识便于调试
