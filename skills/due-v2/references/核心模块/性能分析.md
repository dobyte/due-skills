# 性能分析 (PProf)

## 概述

性能分析组件基于 Go 标准库 [net/http/pprof](https://pkg.go.dev/net/http/pprof) 实现，作为一个独立的容器组件运行，启动后提供 HTTP 端点用于采集 CPU、内存、协程等运行时性能数据。

## 包路径

```go
import "github.com/dobyte/due/v2/component/pprof"
```

## 配置参数

在 `etc.toml` 配置文件中配置 pprof 参数：

```toml
[pprof]
    # pprof服务器监听地址，默认为:0（随机端口）
    addr = ":0"
```

路由前缀固定为 `/debug/pprof/`，不可通过配置修改。

## 核心 API

```go
// NewPProf 创建 pprof 组件
func NewPProf(opts ...Option) *PProf

// WithAddr 设置监听地址
func WithAddr(addr string) Option

// Start 启动 pprof 服务器（实现 component.Component 接口，由容器调度）
func (p *PProf) Start()

// Name 组件名称，返回 "pprof"
func (p *PProf) Name() string
```

组件内部已并发保护，`Start()` 在协程中启动 HTTP 服务并打印实际访问地址。

## 分析端点

| 端点 | 说明 |
|------|------|
| `/debug/pprof/` | 分析首页，汇总以下全部端点 |
| `/debug/pprof/cmdline` | 当前进程启动命令行 |
| `/debug/pprof/profile` | CPU 性能采样，默认采样 30s，可通过 `?seconds=N` 调整 |
| `/debug/pprof/symbol` | 程序计数器到函数符号的映射 |
| `/debug/pprof/trace` | 协程执行追踪，默认 1s，可通过 `?seconds=N` 调整 |

堆内存、协程、锁等 profile 可通过首页链接或 `go tool pprof` 直接访问（如 `/debug/pprof/heap`、`/debug/pprof/goroutine`、`/debug/pprof/block`、`/debug/pprof/mutex`）。

## 使用示例

### 注册到容器

```go
package main

import (
    "github.com/dobyte/due/v2"
    "github.com/dobyte/due/v2/component/pprof"
    "github.com/dobyte/due/v2/cluster/node"
)

func main() {
    container := due.NewContainer()
    // 创建节点组件
    component := node.NewNode()
    // 添加节点组件
    container.Add(component)
    // 添加 pprof 组件
    container.Add(pprof.NewPProf(pprof.WithAddr("0.0.0.0:6060")))
    // 启动容器
    container.Serve()
}
```

启动后终端会输出访问地址，如 `PProf Url: http://127.0.0.1:6060/debug/pprof/`。

### 命令行采集

```bash
# 采集 30s CPU 火焰图数据并进入交互分析
go tool pprof http://127.0.0.1:6060/debug/pprof/profile?seconds=30

# 采集堆内存数据
go tool pprof http://127.0.0.1:6060/debug/pprof/heap

# 采集协程信息
go tool pprof http://127.0.0.1:6060/debug/pprof/goroutine

# 采集执行追踪
curl -o trace.out "http://127.0.0.1:6060/debug/pprof/trace?seconds=5"
go tool trace trace.out

# 浏览器查看可视化面板
http://127.0.0.1:6060/debug/pprof/
```

## 最佳实践

1. **固定端口**：默认 `addr = ":0"` 会随机分配端口，采集时建议显式指定端口（如 `:6060`）。
2. **内网隔离**：pprof 端点会暴露进程内部信息，生产环境应绑定内网地址（如 `127.0.0.1:6060` 或内网 IP），严禁直接暴露公网。
3. **按需开启**：仅在需要排查性能问题时启用，无需所有实例常驻开启。
4. **采样影响**：CPU 采样（profile）与追踪（trace）期间会带来一定性能开销，建议在低峰期或压测环境采集。
