# 网关服务器 (Gate)

## 概述

网关服务器（gate）是 Due 框架集群架构的前端入口，负责处理客户端连接、协议解析、消息转发等核心功能。支持 TCP 和 WebSocket 协议，提供高性能的网关服务。

## 包路径

```go
import "github.com/dobyte/due/v2/cluster/gate"
```

## 配置参数

```toml
[cluster.gate]
    # 实例ID，集群中唯一。不填写默认自动生成唯一的实例ID
    id = ""
    # 实例名称

    dispatch = "random"
    # 内建RPC服务器监听地址。不填写默认随机监听
    addr = ":0"
    # 是否将内建RPC通信地址暴露到公网。默认为false
    expose = false
    # 实例元数据
    [cluster.gate.metadata]
        # 键值对，且均为字符串类型。由于注册中心的元数据参数限制，建议将键值对的数量控制在20个以内，键的字符长度控制在127个字符内，值的字符长度控制在512个字符内
        key = "value"

    [cluster.gate.linker]
        # RPC连接数，默认5
        connNum = 5
        # RPC调用超时时间，支持单位：纳秒（ns）、微秒（us | µs）、毫秒（ms）、秒（s）、分（m）、小时（h）、天（d）。默认为3s

        faultRecoveryTime = "5s"
```

### 内置处理流程

网关组件不对外暴露代理对象，客户端连接的接入与消息转发由内部处理流程完成：

- `OnConnect`：连接建立时，若网关处于 Work 或 Busy 状态，则将连接加入 `session.Session` 并触发 `Connect` 事件；否则直接关闭连接。
- `OnDisconnect`：连接断开时，从 `session.Session` 移除连接；若连接已绑定用户则解除绑定，并触发 `Disconnect` 事件。
- `OnReceive`：收到消息时，解析路由号与序列号，并将消息投递到对应的业务节点（未命中路由或端点时仅记录日志）。
- `Reconnect`：用户重新绑定到网关时触发 `Reconnect` 事件。

上述事件均由网关转发给持有用户定位的业务节点。

## 使用示例

### 基础网关服务器

```go
package main

import (
    "github.com/dobyte/due/locate/redis/v2"
    "github.com/dobyte/due/network/tcp/v2"
    "github.com/dobyte/due/registry/consul/v2"
    "github.com/dobyte/due/v2"
    "github.com/dobyte/due/v2/cluster/gate"
)

func main() {
    // 创建容器
    container := due.NewContainer()
    // 创建网络服务器
    server := tcp.NewServer()
    // 创建用户定位器
    locator := redis.NewLocator()
    // 创建服务发现
    registry := consul.NewRegistry()
    // 创建网关组件
    component := gate.NewGate(
        gate.WithServer(server),
        gate.WithLocator(locator),
        gate.WithRegistry(registry),
    )
    // 添加网关组件
    container.Add(component)
    // 启动容器
    container.Serve()
}
```

WebSocket 网关只需把网络服务器替换为 `ws.NewServer()`（`github.com/dobyte/due/network/ws/v2`），其余代码保持不变。

### 配置分发策略与连接器

```go
package main

import (
    "time"

    "github.com/dobyte/due/locate/redis/v2"
    "github.com/dobyte/due/network/tcp/v2"
    "github.com/dobyte/due/registry/consul/v2"
    "github.com/dobyte/due/v2/cluster"
    "github.com/dobyte/due/v2/cluster/gate"
)

func main() {
    component := gate.NewGate(
        gate.WithServer(tcp.NewServer()),
        gate.WithLocator(redis.NewLocator()),
        gate.WithRegistry(consul.NewRegistry()),
        // 无状态路由消息分发策略
        gate.WithDispatch(cluster.RoundRobin),
        // 内建RPC连接器参数
        gate.WithLinkerConnNum(5),
        gate.WithLinkerCallTimeout(3*time.Second),
    )

    _ = component
}
```

## 事件类型

网关在处理客户端连接时，会向业务节点触发以下集群事件（`cluster.Event`）：

```go
const (
    // 连接建立
    Connect = cluster.Connect
    // 连接断开后重新连接
    Reconnect = cluster.Reconnect
    // 连接断开
    Disconnect = cluster.Disconnect
)
```

## 状态类型

网关通过集群状态（`cluster.State`）标识自身可用性，运行期间仅允许在 Work 与 Busy 之间切换：

```go
const (
    // 关闭，不可访问
    Shut = cluster.Shut
    // 健康，可继续分配
    Work = cluster.Work
    // 繁忙，不再接收新连接
    Busy = cluster.Busy
    // 挂起，准备销毁
    Hang = cluster.Hang
)
```

## 最佳实践

1. **连接管理**:
   - 合理设置最大连接数防止资源耗尽
   - 启用心跳检测及时清理死连接

2. **安全性**:
   - 为网络服务器配置证书（certFile/keyFile）启用 TLS 保护通信
   - 通过业务节点的加密器保护跨集群消息内容

3. **消息转发**:
   - 合理设计消息路由规则
   - 使用用户定位器追踪用户位置

4. **性能优化**:
   - 通过 `dispatch` 选择合适的分发策略
   - 按需调整 `linker` 的连接数与队列大小

5. **监控告警**:
   - 在业务节点监听连接、重连与断开事件统计在线人数
   - 监控消息转发延迟和成功率
