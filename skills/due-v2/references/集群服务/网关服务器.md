# 网关服务器 (Gate)

## 概述

网关服务器（gate）是 Due 框架集群架构的前端入口，负责处理客户端连接、协议解析、消息转发等核心功能。支持 TCP 和 WebSocket 协议，提供高性能的网关服务。

## 包路径

```go
import "github.com/dobyte/due/v2/cluster/gate"
```

## 配置参数

```toml
[cluster.gate]
    # 实例ID，集群中唯一。不填写默认自动生成唯一的实例ID
    id = ""
    # 实例名称
    name = "gate"
    # 无状态路由消息分发策略。支持策略：随机（random）、轮询（rr）、加权轮询（wrr）。默认为random
    dispatch = "random"
    # 内建RPC服务器监听地址。不填写默认随机监听
    addr = ":0"
    # 是否将内建RPC通信地址暴露到公网。默认为false
    expose = false
    # 实例元数据
    [cluster.gate.metadata]
        # 键值对，且均为字符串类型。由于注册中心的元数据参数限制，建议将键值对的数量控制在20个以内，键的字符长度控制在127个字符内，值的字符长度控制在512个字符内
        key = "value"
    # 集群内RPC连接器配置
    [cluster.gate.linker]
        # RPC连接数，默认5
        connNum = 5
        # RPC调用超时时间，支持单位：纳秒（ns）、微秒（us | µs）、毫秒（ms）、秒（s）、分（m）、小时（h）、天（d）。默认为3s
        callTimeout = "3s"
        # RPC拨号超时时间，默认3s
        dialTimeout = "3s"
        # RPC拨号重试次数，默认3
        dialRetryTimes = 3
        # RPC连接故障恢复时间，默认5s
        faultRecoveryTime = "5s"
        # 命令队列大小，默认4096
        commandQueueSize = 4096
        # 命令写入超时时间，默认0s（不超时）
        commandWriteTimeout = "0s"

[network.tcp.server]
    # 服务器监听地址。`:3553` 默认 IPv4/IPv6 双栈；`0.0.0.0:3553` 仅 IPv4（v2.6.7 起）
    addr = ":3553"
    # 最大连接数，默认为5000
    maxConnNum = 5000
    # 私钥文件
    keyFile = ""
    # 证书文件
    certFile = ""
    # 心跳间隔时间，默认为10s
    heartbeatInterval = "10s"
    # 心跳机制，默认为resp。可选：resp（响应式心跳）| tick（定时主推心跳）
    heartbeatMechanism = "resp"
    # 授权超时时间，默认为0s（不进行授权检测）
    authorizeTimeout = "0s"

# Gate 内置 per-connection GCRA 限流器（v2.6.7 新增，整数 GCRA 算法，独立于 limiter 子模块）
# 注意：这是 cluster 层面配置，不属于 network.tcp.server。所有传输协议（TCP/WS/KCP/QUIC）
# 的 Gate limiter 配置统一；quota=0 表示关闭限流（默认）
[cluster.gate.limiter]
    # 窗口周期，默认 1s
    period = "1s"
    # 窗口内允许的业务帧数；0 表示关闭（默认），推荐生产 >= 1000
    quota = 0
    # 突发容量（GCRA τ），默认 ceil(quota)
    burst = 0
    # 连续违规多少次后强制关闭连接，默认 100
    closeThreshold = 100

[packet]
    # 字节序，默认为big。可选：little | big
    byteOrder = "big"
    # 路由字节数，默认为2字节
    routeBytes = 2
    # 序列号字节数，默认为2字节
    seqBytes = 2
    # 消息字节数，默认为5000字节
    bufferBytes = 5000
    # 是否携带服务器心跳时间
    heartbeatTime = false
```

### 内置处理流程

网关组件不对外暴露代理对象，客户端连接的接入与消息转发由内部处理流程完成：

- `OnConnect`：连接建立时，若网关处于 Work 或 Busy 状态，则将连接加入 `session.Session` 并触发 `Connect` 事件；否则直接关闭连接。
- `OnDisconnect`：连接断开时，从 `session.Session` 移除连接；若连接已绑定用户则解除绑定，并触发 `Disconnect` 事件。
- `OnReceive`：收到消息时，解析路由号与序列号，并将消息投递到对应的业务节点（未命中路由或端点时仅记录日志）。
- `Reconnect`：用户重新绑定到网关时触发 `Reconnect` 事件。

上述事件均由网关转发给持有用户定位的业务节点。

## 使用示例

### 基础网关服务器

```go
package main

import (
    "github.com/dobyte/due/locate/redis/v2"
    "github.com/dobyte/due/network/tcp/v2"
    "github.com/dobyte/due/registry/consul/v2"
    "github.com/dobyte/due/v2"
    "github.com/dobyte/due/v2/cluster/gate"
)

func main() {
    // 创建容器
    container := due.NewContainer()
    // 创建网络服务器
    server := tcp.NewServer()
    // 创建用户定位器
    locator := redis.NewLocator()
    // 创建服务发现
    registry := consul.NewRegistry()
    // 创建网关组件
    component := gate.NewGate(
        gate.WithServer(server),
        gate.WithLocator(locator),
        gate.WithRegistry(registry),
    )
    // 添加网关组件
    container.Add(component)
    // 启动容器
    container.Serve()
}
```

WebSocket 网关只需把网络服务器替换为 `ws.NewServer()`（`github.com/dobyte/due/network/ws/v2`），其余代码保持不变。

### 配置分发策略与连接器

```go
package main

import (
    "time"

    "github.com/dobyte/due/locate/redis/v2"
    "github.com/dobyte/due/network/tcp/v2"
    "github.com/dobyte/due/registry/consul/v2"
    "github.com/dobyte/due/v2/cluster"
    "github.com/dobyte/due/v2/cluster/gate"
)

func main() {
    component := gate.NewGate(
        gate.WithServer(tcp.NewServer()),
        gate.WithLocator(redis.NewLocator()),
        gate.WithRegistry(consul.NewRegistry()),
        // 无状态路由消息分发策略
        gate.WithDispatch(cluster.RoundRobin),
        // 内建RPC连接器参数
        gate.WithLinkerConnNum(5),
        gate.WithLinkerCallTimeout(3*time.Second),
    )

    _ = component
}
```

## 事件类型

网关在处理客户端连接时，会向业务节点触发以下集群事件（`cluster.Event`）：

```go
const (
    // 连接建立
    Connect = cluster.Connect
    // 连接断开后重新连接
    Reconnect = cluster.Reconnect
    // 连接断开
    Disconnect = cluster.Disconnect
)
```

## 状态类型

网关通过集群状态（`cluster.State`）标识自身可用性，运行期间仅允许在 Work 与 Busy 之间切换：

```go
const (
    // 关闭，不可访问
    Shut = cluster.Shut
    // 健康，可继续分配
    Work = cluster.Work
    // 繁忙，不再接收新连接
    Busy = cluster.Busy
    // 挂起，准备销毁
    Hang = cluster.Hang
)
```

## 最佳实践

1. **连接管理**:
   - 合理设置最大连接数防止资源耗尽
   - 启用心跳检测及时清理死连接

2. **安全性**:
   - 为网络服务器配置证书（certFile/keyFile）启用 TLS 保护通信
   - 通过业务节点的加密器保护跨集群消息内容

3. **消息转发**:
   - 合理设计消息路由规则
   - 使用用户定位器追踪用户位置

4. **性能优化**:
   - 通过 `dispatch` 选择合适的分发策略
   - 按需调整 `linker` 的连接数与队列大小

5. **监控告警**:
   - 在业务节点监听连接、重连与断开事件统计在线人数
   - 监控消息转发延迟和成功率

6. **连接级限流（v2.6.7 推荐生产启用）**:
   - 配置路径：`[cluster.gate.limiter]`（cluster 层面，不是 network.tcp.server）
   - `quota` 设为 > 0 的 float64 即启用；默认 0 表示关闭
   - 推荐生产值：quota=1000、period=1s、burst=2000、closeThreshold=100
   - Go Option 覆盖：`gate.WithLimiterQuota(1000)` / `WithLimiterPeriod(time.Second)` / `WithLimiterBurst(2000)` / `WithLimiterCloseThreshold(100)`
   - 限流触发的 Close 是异步的（defer 到 read loop 外），不会阻塞关闭流程
   - 只限制业务帧；握手帧和心跳帧自动绕过

7. **IPv6 双栈（v2.6.7）**:
   - `addr = ":3553"` 默认双栈，生产环境如需要纯 IPv4 显式写 `0.0.0.0:3553`

## 版本更新摘要

### v2.6.7

**新特性**:
- **内置 per-connection GCRA 限流器**（etc 配置 `etc.cluster.gate.limiter.{quota,period,burst,closeThreshold}`；Go Option `WithLimiterQuota(float64)` / `WithLimiterPeriod(time.Duration)` / `WithLimiterBurst(int)` / `WithLimiterCloseThreshold(int)`）：整数 GCRA、256 shard sync.Map bucket + free list 复用、cache line padding、lazily 创建 bucket、close defer 到 read loop 外防死锁、close retry 节流、violation counter cap 防 overflow。独立于 limiter 子模块（Gate 自实现 connLimiter）
- **Connect/Disconnect 事件 per-connection 串行化**，connect handler 统一在 read goroutine 上运行
- **IPv4/IPv6 双栈监听**：`:port` 默认双栈
- **Register/Refresh/Deregister 串行化**（registry mutex），Destroy 时同步关闭 linker 缓存的 RPC 客户端
- **Session 原子计数器**：`Stat` 变为 O(1) atomic load

**行为修正**:
- limiter 触发的 Close 之前同步关闭 read goroutine 会死锁，现在 defer 到 loop 外
- 批量推 fan-out 从每 session 启一个 goroutine 改为 bounded 64 并发
- 未 admit 的连接也会释放 limiter bucket

### v2.6.5

**性能**:
- Push 走 direct/indirect helper，跳过 Multicast 包装
- 所有 codec 实现 `encoding.Appender`，link 编码走 pooled buffer in-place prepend
